- **worker 接收图片/文件等非文本消息（2026-11-16）**：微信侧非文本消息本身不带地址，新增**收件人模式**——`#<编号>` / `发给任务 <编号>` 只把任务设为收件人（`任务：` / `#<编号> 正文` / `继续` 顺带设置），之后不带前缀的文字与附件都交给该任务。附件先入内存待投递队列（首批回执 `📎 已把收到的附件交给 #N…`），下一句文字或 `好了`/`就这样` 时经 `prepareInboundMedia()`（`daemon/messaging/inbound-media.ts`，从 `index.ts` 抽出的 brain 媒体管线）下载解密，图片以 ACP `image` 块、文件/视频/无转写语音以本地路径说明并入同一个 `injectTask(..., { images })` 回合；`applyMediaToPrompt()`（`acp/prompt-media.ts`）让 brain 与 worker 共用同一套「不支持图片就给明确说明、不臆测内容」的降级。收件人按发送者隔离、内存态（`daemon/media-route.ts` 的 `MediaRoute`），静默 3 分钟（`WEMIND_MEDIA_RECIPIENT_TTL_MS`，默认 `180000`）滑动超时自动退出并把队列里的附件补交回去，`回到大脑` / `/to-brain` 主动退出，`问大脑：…` 只逃逸一句，任务结束或 `结束任务` 自动清除。**未设收件人时行为不变**：带附件的消息仍一律交给大脑（`isFastLane()` / `shouldResumeInBrainQueue()` 的安全降级保留）。
- **brain 逃逸前缀扩展**：除 `问大脑` 外新增 `大脑：xxx` / `大脑 xxx` 与 `brain: xxx` / `brain xxx`（大小写不敏感，必须带冒号或空格）；不带斜杠，避免与 `切换大脑` 的 `/brain` 冲突。
- **worker 任务结果可以发图片/文件/视频（2026-11-16）**：worker 在结果里写 `![](本地路径或 http 直链)`、`[附件](file:///绝对路径)` / `[文件](…)` / `[视频](…)`，daemon 用与大脑相同的出站管线（`sendReplyMedia()`：`extractImages()` / `extractAttachments()` → `resolveImageBytes()` / `resolveAttachment()`）解析成独立媒体消息再发正文。每张图片/每个文件各占一条连发额度；敏感文件同样被 denylist 拦截，「允许敏感文件」窗口内放行；失败时正文里保留原路径并附说明。worker 每个任务会话首轮会收到一次「可发图/发文件」约定提示（`hintedSessions`）。同一用户的多条任务推送按顺序串行（媒体要先下载/读盘）。任务推送末尾的提示改为「不带前缀的消息**默认**交给大脑（发「#N」可设为收件人）」，收件人模式下不再误导。

### Changed

- **`结束全部任务` 连「待继续」的记录一起清（2026-11-17）**：此前 `结束全部任务` 只看「在跑」，一堆「待继续」时回 `当前没有正在运行的任务。`——用户以为已经收完，列表里却还挂着一串。现在不带编号的「全部结束」会连记录一起清并逐个列出；真的什么都没有时回 `没有要结束的任务：现在没有在跑、也没有待继续的。`；单条 `结束任务`（无编号、无在跑）的文案也从「当前没有正在运行的任务」改为「现在没有在跑的任务」+ 待继续条数提示。

- **新增 `全部继续` / `全部结束`（2026-11-17）**：`全部继续`（`继续全部` / `/resume all`）把停在半路（「待继续」）的任务一起拉起来并行跑，回执列出编号并提示它们并行；`结束全部任务` 之外补了同义的 `全部结束` / `结束所有任务`。此前多任务并存时只能逐条 `#<编号> 继续`，重启一次就积一批「待继续」，手机上逐条发很麻烦。
- **任务列表改成 markdown 表格（2026-11-17，三次调整）**：先是「块 + 空行」，真机上没改善（微信客户端会把连续空行压成一行），换分隔线后仍然太长；中间一版是「一条任务一行」，最后按用户反馈改成 **markdown 表格**——第一列 `▶️/💬/⏸️` 图标（运行中/等你回复/待继续），其余列 `#编号 agent` / 状态 / 轮次 / 时长，标题带待继续计数（`📋 任务（6 条 · 3 个待继续）`）；非运行中任务的最近输出不进表格（会把列撑爆），放表下逐条 `**#5** …`（单行、≤80 字）。**微信能渲染 markdown 表格**（此前「不渲染」的判断是错的，已纠正）；单元格里的 `|` 与反引号需先转义（`cell()`），空行仍会被压掉。`任务列表` 快车道回执补了日志 `task: list(<user>)`，事后能从 `daemon.log` 核实。
- **`任务：xxx` / `>xxx` 一律新建任务（2026-11-17）**：此前是「有活跃任务就发给它/追加」——而活跃与否是用户看不见的状态（`waiting` 也算活跃），同一句话时而新建、时而被旧任务吞掉。现在 `index.ts` 的 `toWorker` 分支只调 `dispatchTask`，要接着某条说请用 `#<编号> 正文` 或先把它设为收件人；并行发生时回执带一句教学（`parallelTaskHint()`：`#N 还在跑，两条并行；要接着它说就发「#N 正文」…`）。`任务 <agent>：…` 原本就是新建，行为不变。
- **收件人默认等待时间 1 分钟 → 3 分钟（2026-11-17）**：`WEMIND_MEDIA_RECIPIENT_TTL_MS` 默认值改 `180000`。一次发一组图（每张都是一条消息）再加一句说明，很容易超过 1 分钟，太短会在中途悄悄切回大脑。
- **任务状态「已中断」改名「待继续」，任务列表排版适配手机（2026-11-17）**：`已中断` 读起来像「已经结束」，而它恰恰是**没跑完、可以接着跑**（进程不在了，发「继续」/`#N 继续` 就能续上）。`task-manager.ts` 的 `STATUS_LABEL` 与 CLI `task-list` 的同一处文案都改为 `待继续`，`重启：N 条…转为「待继续」`、`有 N 条任务停在半路（待继续），请指明编号：…` 一并改口。`renderTaskList()` 改为**每条任务之间空一行**（手机上连着 6 条会糊成一坨），`cwd` 挪到单独一行，并在有「待继续」任务时附一句状态说明：`「待继续」= 进程不在了，发「继续」（或「#N 继续」）接着跑；上一步可能已经改过文件，先核对。不要的用「结束任务 <编号>」清掉。`
- **收件人提交前等「后到的图」并批（2026-11-17）**：微信里一张图就是一条消息，用户「连发几张 + 立刻发文字」时最后几张往往还在路上，原先会被挤到下一个回合（看起来像「少发了一张」）。现在触发提交（文字 / `好了`）且队列非空时，先等附件队列**安静 700ms**（`WEMIND_MEDIA_FLUSH_DEBOUNCE_MS`，`0` 关闭）再取，晚到的附件并入同一批；总等待上限 3 秒，避免用户一直发图时已发出的文字永远等下去。只对用户触发的提交生效，TTL 到期 / 换收件人 / `回到大脑` / `结束任务` 一律立即处理。
- **收件人超时回执加自我标识（2026-11-17）**：文案改为 `⌛ 提醒：收件人 #N 已超时自动取消，之后的文字和附件交给大脑。` 并附一行「这是定时器单独发的提醒，不是对你上一条消息的回复」——它是 15s 清扫定时器发的，常被误读成对刚发那句任务的回复。**同日再改**：附件去向不再写成「（把已收到的附件交回去时：…）」这种从句，改为先说结论 `📎 超时前收到的 N 个附件已交给 #N。`（交不出去时 `没能交给 #N。` 加原因），任务自己的回话（续跑提示之类）另起一行原样附上；判据用 `deliverPending()` 的 `onOutcome`。

### Fixed

- **代码围栏 / 行内代码里的媒体语法不再被当成真要发的附件（2026-11-17，真机发现）**：worker 只是解释用法（「视频写 `[视频](file:///…)` 这样」「图片直接写 `![](路径)` 就行」），daemon 却按示例去读盘/下载，失败后还在答复末尾追加「有 N 个附件没能下载」。现在 `maskCodeRegions()`（`daemon/messaging/markdown-code.ts`）先把围栏代码块与行内代码遮成**等长空白**，`extractImages()` / `extractAttachments()` 只在正文里匹配；正文里的真图片/真附件照常发。
