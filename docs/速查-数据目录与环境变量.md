# 速查 · 数据目录与环境变量

> 一页纸速查。完整说明见 [`repowiki/08-数据存储与多账号.md`](repowiki/08-数据存储与多账号.md)、[`repowiki/09-配置项与环境变量.md`](repowiki/09-配置项与环境变量.md)；权威实现见 `packages/wechat-ilink-core/src/store/accounts.ts`、`store/account.ts`。
>
> 命令统一用已安装的 **`wemind`**（`npm i -g @wemind/cli`；不安装则 `npx -y @wemind/cli …`；从源码运行等价于 `node packages/wechat-daemon/dist/cli.js <子命令>`）。示例中的 `<新数据目录>`、`<账号key或备注>` 请换成你自己的值。

## 1. 数据目录解析（优先级从高到低）

```
账号数据目录 DATA_DIR =
  WECHAT_DATA_DIR                        # ① 完整路径，最高优先级
  否则  <WEMIND_ROOT> / <WECHAT_ACCOUNT>  # ② WECHAT_ACCOUNT 默认 = default

根目录 WEMIND_ROOT =
  WEMIND_HOME                            # 否则 ~/.wemind

账号注册表 = <WEMIND_ROOT>/accounts.json
```

**一句话**：整体搬家（注册表 + 所有账号 + 日志）→ 改 **`WEMIND_HOME`**；只想给「某个运行的进程」换账号数据目录 → **`WECHAT_DATA_DIR`**。

> 默认数据目录是 `~/.wemind`（Windows 为 `C:\Users\<你>\.wemind`），**独立于代码目录**——重装、移动或重新 clone 代码都不影响登录态。

## 2. 目录布局

```
<WEMIND_ROOT>/
├── accounts.json         # 账号注册表（key → 元数据 + 默认账号）
├── .staging/             # 登录暂存（login 用，归档后自动删）
└── <key>/                # 每个账号一份（key 由微信 botId 派生，唯一）
    ├── account.json          # 登录凭证（Bot Token；Windows 下明文⚠️）
    ├── state.json            # 长轮询游标（读到哪了）+ context_token + 去重 id
    ├── allowFrom.json        # 登录者白名单（兜底，默认只放行登录者）
    ├── brain-sessions.json   # <agent>:userId → 大脑 ACP sessionId（换大脑各自保留；「当前是哪个」的唯一权威）
    ├── session-registry.json # 会话登记表（名字/标题/轮次/最近使用；上限 50 条/(人·大脑)，只供列表展示）
    ├── brain.json            # 大脑选择（agent=…；未配置→自动探测，见 接入其它-ACP-Agent.md）
    ├── brain-mcps.json       # 大脑当前激活的 MCP 集（默认空）
    ├── brain-home/           # 大脑沙箱（如 opencode/opencode.json、qoder/settings.json + qoder/.auth/）
    ├── handoff.json          # 交接摘要（`交接` 生成；TTL 24h，切到别的大脑后第一条消息带上一次即消费）
    ├── worker-sessions.json  # worker 任务 sessionId（键 <agent>:task-<编号>@<userId>，带编号与用户防撞）
    ├── worker-home/          # worker 沙箱（布局同上）
    ├── task-inbox/           # 本地任务文件桥（CLI 写、daemon 扫；命令带 ack 答复编号）
    ├── task-out/             # 本地任务的答复（daemon 写、CLI 短轮询后删；派发的答复等起进程有结果才写）
    ├── tasks.json            # 任务表（重启后续跑用：未完成的标「已中断」，回「继续」才续跑；损坏降级为空表）
    ├── task-state.json       # 任务状态记录（顶层字段复制最近一条任务，另有 tasks 数组；旧版 CLI 读不错）
    ├── control-inbox/        # CLI → daemon 控制请求（切脑 / 会话命令）
    ├── control-out/          # daemon → CLI 应答；.bridge 记 daemon 的 pid（判「旧版本 daemon」的凭据）
    ├── daemon.log            # 运行日志（wrapper + daemon 共写此处）
    ├── pm2.app.json          # 仅 --runner pm2：pm2 的 app 声明（重拉策略/日志/WECHAT_ACCOUNT）
    ├── wrapper.pid           # 裸整数：停后台守护进程
    ├── daemon.pid            # 裸整数：定位本账号 node 进程
    ├── brain.pid             # JSON 身份记录（单条）：pid/agent/bin/args/shell/state/时间戳
    └── workers.pid.json      # JSON 记录数组：每条一个 worker（state=busy|idle、taskId、时间戳）
```

> **PID 文件为什么是 JSON（1.2.0）**：`brain.pid` / `workers.pid.json` 记下起进程时**真实用的** `bin`/`args`，`wemind stop`/`list` 按它算进程特征串——配置里改过 agent、刚换过大脑、多任务多 agent 并存时都不会认错。`wrapper.pid` / `daemon.pid` 仍是裸整数。旧账号只有裸整数 `worker.pid`（没有 `workers.pid.json`）时仍兼容读——判定回退到「用**配置里**的 bin/args 算特征串」的旧行为；而 `workers.pid.json` 里的 legacy/缺字段记录（没有可用特征串）会被判为「不是我们的进程」跳过、不杀（安全侧）。反向不兼容：旧版 CLI 读 JSON pid 文件会显示「已停止」但**不杀进程**（同样是安全侧取舍）。

## 3. 环境变量速查（数据目录 / 账号）

| 变量 | 默认 | 作用 | 定义位置 |
|---|---|---|---|
| `WEMIND_HOME` | `~/.wemind` | 数据**根目录**（注册表 + 所有账号） | core `store/accounts.ts` |
| `WECHAT_ACCOUNT` | `default` | 账号子目录名（`<根>/<此值>`） | core `store/account.ts` |
| `WECHAT_DATA_DIR` | — | 直接指定**账号数据目录**（覆盖 ②，**不改注册表位置**） | core `store/account.ts` |

> ⚠️ `WEMIND_ROOT` / `DATA_DIR` 都在**模块加载时**求值 → 这几个变量必须**在进程启动之前**设好（运行中改无效）。

### 3.1 运行期调参（1.2.0：进程池 / 换大脑 / 控制桥 / 交接）

| 变量 | 默认 | 作用 | 定义位置 |
|---|---|---|---|
| `WEMIND_MAX_WORKERS` | `3` | 并发任务上限（worker 进程池）；**超限直接拒绝派发**，不排队 | daemon `worker-pool.ts` |
| `WEMIND_IDLE_MAX` | `2` | 保留的空闲 worker 进程上限（超出从最旧的开始回收） | daemon `worker-pool.ts` |
| `WEMIND_WORKER_REAP_MS` | `300000`（5 分钟） | 空闲超时回收 worker 进程（**不是** `WEMIND_WORKER_IDLE_MS`——那是单轮 prompt 空闲超时） | daemon `worker-pool.ts` |
| `WEMIND_SWITCH_DRAIN_MS` | `30000` | 换大脑前等在途回合结束的上限；超时 = 诚实失败（不砍回合） | daemon `brain-switch.ts` |
| `WEMIND_SWITCH_TIMEOUT_MS` | `120000` | 切换时新进程启动的硬上限（到点就放弃） | daemon `brain-switch.ts` / `acp-brain.ts` |
| `WEMIND_CONTROL_TIMEOUT_MS` | `30000` | CLI 等 daemon 控制桥应答的上限（切换类命令按 switch 上限放宽） | daemon `control-bridge.ts` |
| `WEMIND_HANDOFF_TTL_MS` | `86400000`（24h） | `交接` 摘要的有效期，过期不再带上 | daemon `handoff.ts` |
| `WEMIND_WORKER_BRAIN` | 未设（回落 `WEMIND_BRAIN`） | 任务 worker 的大脑 agent 名；环境变量优先级高于 `brain.json`，设了会压住 `brain switch --worker` 的写入磁盘结果 | daemon `brain-agents.ts` |
| `WEMIND_ACP_SESSION_MODE` | 未设（用预设 `sessionMode`） | 覆盖/关闭预设的会话模式（`session/set_mode`）：`0`/`false`/`off` 关闭（回到 agent 自己的审批流程），其它非空值 = 该 modeId；影响 claude-code / codex 的免审批 | daemon `brain-agents.ts` |
| `WEMIND_SESSION_LOG_MAX` | `50` | 会话登记表每个（人 · 大脑）的条数上限，超出先淘汰「未命名且最旧」的 | daemon `session-registry.ts` |

> 这些多是**模块加载期**读的常量，且读的是**进程自己的**环境：改 daemon 侧的要 `wemind stop <账号> && wemind start <账号>` 才生效。

## 4. 初次运行：想指定数据目录

首次登录前选一种方式即可。**全新开始不需要「迁移」**，只要在**第一次 `login` 之前**设好/建好，数据就会直接落到你想要的位置。

### 4.1 方式一：什么都不做（默认）

数据落在 `~/.wemind`（Windows：`C:\Users\<你>\.wemind`）。适合不挑磁盘位置的场景。

### 4.2 方式二：用 `WEMIND_HOME` 指定（跨平台，官方）

**Windows（PowerShell）：**

```powershell
# 只在当前窗口生效
$env:WEMIND_HOME = "<新数据目录>"

# 永久生效（新终端、开机自启都会带上）——设一次即可
setx WEMIND_HOME "<新数据目录>"
```

**macOS / Linux：**

```bash
# 只在当前终端生效
export WEMIND_HOME="<新数据目录>"

# 永久生效：写进 shell 配置（bash 用 ~/.bashrc，zsh 用 ~/.zshrc）
echo 'export WEMIND_HOME="<新数据目录>"' >> ~/.bashrc
```

然后照常首次登录：

```bash
wemind login --label <你的备注> --start
```

数据即落到 `<新数据目录>/<账号key>/`，日志是同目录下的 `daemon.log`。

> 关键：环境变量要在**进程启动之前**设好（见 §9）。如果只用当前窗口临时设，请**在同一个窗口里**执行 `wemind login/start`，否则 daemon 拿不到。

### 4.3 方式三：把默认位置「接到新盘」（最省心，之后不用管环境变量）

让 `~/.wemind` 直接指向新目录，程序眼里还是默认路径，实际写入新位置：

**Windows（Junction，无需管理员）：**

```powershell
# 目标目录先建好
New-Item -ItemType Directory -Force "<新数据目录>" | Out-Null

# 把默认路径接到目标（前提：~/.wemind 尚不存在）
New-Item -ItemType Junction -Path "$env:USERPROFILE\.wemind" -Target "<新数据目录>"
```

**macOS / Linux（软链接）：**

```bash
mkdir -p "<新数据目录>"
ln -s "<新数据目录>" ~/.wemind
```

之后照常 `wemind login ...`，无需任何环境变量——所有命令、日志、自启都无需改动。

## 5. 运行之后：迁移数据目录

已经跑过（有登录态/数据）再换位置，通用步骤是：**停 → 搬 → 指过去 → 重启 → 验证**。

迁移前**务必先停掉 daemon**，否则数据文件被占用（尤其 Windows）：

```bash
wemind stop <账号key或备注>     # 省略参数则停默认账号；多个账号分别停
```

### 5.1 搬运数据

把整个旧根**原样**搬到新目录：

```powershell
# Windows：/MOVE = 搬迁（搬完删源）；robocopy 退出码 0–7 都表示成功
robocopy "$env:USERPROFILE\.wemind" "<新数据目录>" /E /MOVE
```

```bash
# macOS / Linux
cp -a ~/.wemind "<新数据目录>"     # 想保留旧目录就先复制，确认无误再删
```

> 想稳妥一点，可先**只复制不删**（Windows 去掉 `/MOVE`），确认重启后一切正常，再删旧目录。

### 5.2 让程序指向新位置（二选一）

- **A. 做成交接点（推荐，之后完全不用管环境变量）**——迁移完旧路径已空，把它接到新目录：

  ```powershell
  # 若旧的 ~/.wemind 还在（空壳），确认已搬空后删掉，再建交接点
  New-Item -ItemType Junction -Path "$env:USERPROFILE\.wemind" -Target "<新数据目录>"
  ```
  ```bash
  # macOS / Linux
  rm -rf ~/.wemind && ln -s "<新数据目录>" ~/.wemind
  ```

- **B. 改用 `WEMIND_HOME`（跨平台）**——永久指向新目录（方法同 §4.2）：

  ```powershell
  setx WEMIND_HOME "<新数据目录>"          # 永久
  $env:WEMIND_HOME = "<新数据目录>"        # 当前窗口也设一下，便于马上重启
  ```

### 5.3 重启并验证

```bash
wemind list                    # 应仍能列出原账号
wemind start <账号key或备注>
wemind list                    # 看到「运行中(pid …)」即成功
```

### 5.4 注意事项

- 若用**计划任务 / pm2** 自启：方式 B 要确保它们的启动环境也带上新位置（写入任务的环境变量，或 `ecosystem.config.cjs` 的 `WEMIND_HOME`）；用**方式 A（交接点）则无需任何改动**。
- 迁移后若 `wemind list/start` 找不到账号，通常是**旧进程没停干净**或**新位置没设对**——先 `wemind list` 看是否列得出账号，再排查进程。

## 6. 多账号（同一根下多份目录）

```powershell
$env:WECHAT_ACCOUNT = "work"    # → <根>/work
wemind login --label 工作号 --start

$env:WECHAT_ACCOUNT = "home"    # → <根>/home（另开一个终端/进程）
wemind login --label 家庭号 --start
```

每个账号 = 不同目录 = 不同 token + 各跑一个 daemon，互不冲突。

## 7. 只给单个进程换目录（`WECHAT_DATA_DIR`，注意坑）

```bash
WECHAT_DATA_DIR="<任意完整路径>" wemind daemon
```

> ⚠️ **坑**：`WECHAT_DATA_DIR` 只改「进程用的账号数据目录」，**注册表仍留在 `WEMIND_HOME`**，且管理命令的 `accountDir(key)` 走的是 `WEMIND_HOME`。因此只设 `WECHAT_DATA_DIR` 时，`wemind list/stop` 可能找不到该 daemon 的 pid。**除非有特殊理由，优先用 `WEMIND_HOME`（整体一致）。**

## 8. 看日志 / 重置

```powershell
# 看某账号日志（-Encoding UTF8 防中文乱码；-Wait 持续跟随）
Get-Content "<WEMIND_ROOT>\<账号key>\daemon.log" -Encoding UTF8 -Wait -Tail 30
```

- 重置登录：删 `<账号目录>/account.json` + `state.json`（重新扫码）
- 清空对话记忆：删 `<账号目录>/brain-sessions.json` + `brain-home/sessions/`

## 9. 让 daemon 拿到环境变量（关键）

daemon 由「后台守护进程/pm2」**脱离式**启动，**不会**自动继承你之后在别处设的变量。可靠做法：

- **临时（当前窗口）**：设 `WEMIND_HOME="..."` 后，**在同一个终端**执行 `wemind start`（启动器会把当前环境透传给后台守护进程 → 再传给 daemon）。
- **永久（推荐）**：`setx WEMIND_HOME "..."`（Windows 用户级）或写进 shell 配置 / 计划任务 / 服务环境。
- **用 `scripts/run-daemon.ps1`（计划任务）**：在脚本或任务环境中设 `WECHAT_ACCOUNT` / `WECHAT_DATA_DIR`，脚本据此解析数据目录与日志。
- **用 pm2**：`ecosystem.config.cjs` 支持 `WEMIND_HOME`；多账号按注册表为每账号注入 `WECHAT_ACCOUNT`。
- 多账号在 PowerShell 里用 `Start-Process -Environment @{ WECHAT_ACCOUNT = $key }` **显式传**（靠 `$env:` 继承不可靠）。
- 记不住这些？直接用 §4.3 / §5.2 的**交接点（Junction / 软链接）**——程序始终读默认路径，变量一个都不用设。
