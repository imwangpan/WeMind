# `packages/wechat-daemon/src/` 目录分层与文件拆分设计

> **状态：已实施**（2026-11-06）
>
> **最后核对**：2026-11-06
>
> **依据**：2026-11-05 的目录重构初稿（已于 2026-11-06 实施后删除，内容并入本稿；修订差异见 §13）。本稿修正初稿的统计口径与遗漏，并按用户决定并入 A/B 类大文件拆分（C 类留待后续）。
>
> **实施分支**：`refactor/src-layout`（从 `main` 切出，单独 PR）。

## 1. 目标

1. 给 `src/` 建立分层边界：**8 个一级目录 + 6 个二级目录 + 根入口**（按需分层，不在所有目录下强行建子层），每个目录名回答「这个模块属于哪个子系统」。
2. 同批完成 4 个高收益文件的拆分（A/B 类）：两个「数据/逻辑分离」，两个「无状态模块拆分」。
3. **行为不变**：目录移动是纯 `git mv`；拆分是「移动 + re-export」，不改变任何导出符号、运行时语义、环境变量、命令、数据文件格式或日志文案。
4. 文档同步与代码变更在**同一批提交**内完成，不攒到最后。

- **不改包边界**：仍是单包 `@wemind/cli`，tsdown 仍打单文件 `dist/cli.js`（入口 `src/cli.ts` 留在根）。
- **不动** `wechat-ilink-core` / `wechat-mcp`。
- **不改** 环境变量、CLI/微信命令、数据文件结构、日志文案。

### 5.3 规则

1. **运行时无环。** 用 `import type` 计入边时，唯一回边是 `shared → agents`（`shared/process/pid-record.ts`），编译期擦除，不构成运行时环。`shared/` 代码注释中写明：「shared 只允许 `import type` 向上引用」。
2. **`handoff.ts` 放 `sessions/`**：`acp-brain` 对它的依赖变成 `acp → sessions`；否则 `acp ↔ daemon` 会成环（`daemon → acp` 有 4 条）。
3. **`ipc → agents` 是已声明的例外**：`chat-command-specs` 需要 `ACP_AGENT_PRESETS` 判定 agent 名。不把预设移到 `shared`（那会改变模块归属且违反「不改内容」）。
4. **相对路径按「新位置」计算**：根入口是 `./<dir>/x.js`；一级目录内是 `./x.js`；跨一级是 `../<dir>/x.js`；二级目录向上是 `../x.js`，跨二级是 `../<sibling>/x.js`，跨一级是 `../../<dir>/x.js`。codemod 用 `path.relative` 统一计算，不能套模板。
5. **`cli/` 只向下依赖**：`manage → subcommands` 单向，`subcommands → cli-context` 不反向；`sessions/`、`ipc/` 被上游依赖。
6. **二级目录不新增依赖方向**：§5.2 的 32 条边全部落在 §5.1 已声明的一级边内，不存在「因为拆了子目录才出现」的跨级依赖。

### 7.3 codemod 规则

识别 8 类形态（共 319 处相对引用，其中跨目录需改 **183 处** = 跨一级 151 + 同级跨二级 32）：

| 形态 | 总数 | 需改 |
| --- | --- | --- |
| 静态 `import … from "./x.js"` | 174 | 110 |
| 混合 `import { a, type B } from` | 37 | 23 |
| 纯 `import type … from` | 18 | 14 |
| `export … from` | 5 | 4 |
| `export type … from` | 1 | 1 |
| `await import("./x.js")` | 52 | 9 |
| `typeof import("./x.js")` | 16 | 7 |
| `vi.mock("./x.js")` | 16 | 15 |

改写算法：

1. 以**旧路径**解析 `./x.js`（在 `git mv` 之后运行必须用「新路径 → 旧路径」反向映射）。
2. 目标新路径 = `moveMap[oldTarget]`；源新路径 = `moveMap[currentFile]`。
3. 计算 `posix.relative(dirname(源新路径), 目标新路径)`，保留 `.js` 后缀（`module: NodeNext` 要求）。
4. 结果以 `./` 开头（同目录）或 `../`（跨目录）；根入口为 `./<dir>/x.js`。
5. 跳过测试安全载荷中的 `../evil`/`../escape`（`control-bridge.test.ts`、`task-inbox.test.ts`）与 `vi.mock("@wemind/wechat-ilink-core")`。
6. 断言：改写前 319 处、改写后 0 处无法解析；扫描数 = 预期数。

> 本仓库 `typescript` 7.0.2 不再暴露 Compiler API，且未安装 `oxc-parser`，codemod 只能文本/正则实现；脚本先屏蔽注释中的路径字符串并断言计数，防止误伤。

## 8. 文档同步流程

> **原则：移动一批文件，就同步这一批涉及的文档，不攒到最后。** 一次性补最容易漏，而且漏了没有任何东西会变红。

### 8.1 每批的文档来源（三来源缺一不可）

2. **本设计 §9 的完整清单**：按批次筛选该批涉及的文件。
3. **`git grep "src/<旧路径>"`**：按旧路径全库搜一遍，grep 结果就是这一批的准确位置。

### 8.2 每批操作顺序

1. `git mv` 该批文件（含测试；改名按 §4.2）。
2. 执行该批拆分（如有）。
3. 跑 codemod 改写全库 import。
4. 改该批的脚本/非代码引用（§9）。
5. 改该批的文档路径引用：
   - **结构性文档**：`docs/ai/代码地图.md`（该批文件的行）、`docs/ai/README.md` §6（如需加目录前缀）、`repowiki/01`/`05` 的平铺树（按批增量替换）。
   - **普通文档**：按 grep 结果逐文件改。
   - **自动生成表**：暂不手改，收尾批统一 `npm run docs:tables`。
   - **历史快照**：只加「当时路径，现为 `src/<新路径>`」说明，不改正文。
6. 跑：
   ```bash
   npm run typecheck
   `npx vitest run <该批相关测试>`（或全量）
   npm run doc-impact:check
   pwsh -NoProfile -File scripts/check-docs.ps1
   ```

## 11. 提交与回滚

- **每批一个提交**，共 9 + 1 个。提交信息格式：
  ```
  refactor(daemon): 将 <目录> 移入 src/<目录>/（纯移动）
  refactor(daemon): 拆分 <文件>（行为不变）
  docs: 同步 <目录> 重构后的路径引用
  ```
  若一批内既有移动又有拆分，可合并为：
  ```
  refactor(daemon): src/<目录>/ 分层并拆分 <文件>（行为不变）
  ```
- **不加 Claude 署名**（用户偏好）。
- **回滚**：每批独立 `git revert <sha>`；纯移动批次 revert 不碰逻辑，拆分批次 revert 恢复原文件。合并后整体回滚按批次倒序执行。
