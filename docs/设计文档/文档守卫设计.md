# 文档守卫设计（doc-impact · check-agent-docs · gen-docs-tables）

> **状态**：已实施（2026-11-06） ｜ **最后核对**：2026-11-06
>
> 本文描述**现行实现**，不是历史方案。动机与审计结论见 [`审查-2026-11-05-经验与约束.md`](../审查与质量记录/审查-2026-11-05-经验与约束.md)；命令速查见 [`AGENTS.md`](../../AGENTS.md) §3 与 [`repowiki/11-开发指南`](../repowiki/11-开发指南.md)。

---

## 1. 背景与目标

2026-11-05 的文档审计记录了 30+ 条错误，根因集中在四类。其中占比较高的两类——「同一事实写了 N 遍」和「改了代码忘改文档」——靠人记不住，也靠不住。本设计把这两类问题变成机器检查：

| # | 目标 | 手段 |
|---|---|---|
| 1 | 改代码时自动列出「这次必须同步哪些文档」，没同步就不让提交 | `scripts/doc-impact.mjs` + 规则表 |
| 2 | 每个内置 agent 的接入文档必须包含固定信息 | `scripts/check-agent-docs.mjs` |
| 3 | 环境变量表、预设表、CLI 命令表由代码自动生成 | `scripts/gen-docs-tables.mjs` |
| 4 | 目录重构时强制同步目录结构文档 | `doc-impact` 的 `restructure` 规则 |

**不做的事**：不判断文档内容写得对不对，不替代评审，不生成说明性散文。守卫只回答「有没有改到该改的地方」。

## 2. 总体设计

### 2.1 文件清单

| 文件 | 作用 |
|---|---|
| `scripts/doc-impact.mjs` | 读取 git diff，按规则表判断本次改动该同步哪些文档；`--check` 时缺文档即失败 |
| `scripts/doc-impact.rules.mjs` | 数据文件，不是可执行脚本；12 条「改了什么 → 必须同步哪些文档」的规则 |
| `scripts/check-agent-docs.mjs` | 枚举 `ACP_AGENT_PRESETS`，逐个检查接入文档的结构与索引 |
| `scripts/gen-docs-tables.mjs` | 从代码枚举环境变量/预设/CLI 命令，重写文档里的标记块；`--check` 只比对 |
| `scripts/doc-guards.test.mjs` | 上述脚本的单元测试，随 `npm test` 运行 |
| `.githooks/pre-commit` | 提交前跑 `format:check`、`doc-impact --check --staged`、`check-agent-docs` |
| `.github/workflows/ci.yml` | CI 里跑三个守卫与链接检查；`fetch-depth: 0` 供 merge-base 使用 |
| `package.json` | `verify` 串起全部检查；另有 `doc-impact` / `check:agent-docs` / `docs:tables` 等脚本 |
| `vitest.config.ts` | `include` 增加 `scripts/**/*.test.mjs` |
| `.github/PULL_REQUEST_TEMPLATE.md` | 文档影响与验证项的检查单（人工兜底） |
| `docs/ai/recipes/add-acp-agent.md` | 接新 agent 的产出物清单与「结论来源档位」填写模板 |

### 2.2 数据流

```text
git diff --name-status -M / -U0
        │
        ▼
doc-impact.mjs  ──读──▶  doc-impact.rules.mjs（12 条规则）
        │
        ├─ 未加 --check：打印每条规则要求同步的文档，退出 0
        └─ 加 --check：检查这些文档是否也在本次 diff 里，缺一个退出 1

brain-presets.ts 的 ACP_AGENT_PRESETS ──▶ check-agent-docs.mjs ──▶ 每篇接入文档的结构与索引
packages/**/*.ts、cli/manage.ts、ipc/chat-command-specs.ts ──▶ gen-docs-tables.mjs ──▶ 四处标记块里的表格
```

所有脚本只读文件系统与 git 元数据，不需要网络。唯一的写操作是 `npm run docs:tables`（重新生成标记块），它不进 pre-commit，只由人手动执行并确认 diff。

## 3. 组件设计

### 3.1 `doc-impact.mjs`：改动影响检查

**解决的问题**：现有 CI 不知道「这次 diff 碰了代码却没碰文档」。

```bash
npm run doc-impact        # 只打印：触发了哪些规则、每条要求同步哪些文档
npm run doc-impact:check  # 断言：这些文档也在本次 diff 里；缺一个就 exit 1
```

**diff 的取法**：

- 本地 `--check`：`merge-base(origin/main 或 main, HEAD)` 到工作区；未跟踪文件按新增处理，避免还没 `git add` 时假绿。
- 所有 git 调用带 `core.quotepath=false`：否则中文文件名会被输出成 `"docs/...\345\244..."`，规则里写的文档路径永远对不上；解析层也兼容带引号的路径写法。
- pre-commit：`--staged`，只看暂存区。
- CI：显式 `--base origin/<base_ref>`，并读取 PR 描述里的豁免声明。

**规则输入**：每条规则拿到一个字符串数组——`"M path"` / `"A path"` / `"R old → new"` 这类状态行，加上 `"+path\t<新增行内容>"`。规则用 `trigger(diffLines)` 判断是否命中；声明了 `files` 的规则只会收到这些目录里的行。

**输出示例**（`--check` 时 ✓ 表示已同步、✗ 表示缺）：

```text
[behavior-session] 会话的新建/恢复/改名/删除与交接是用户可见行为……
  需要同步：
    ✗ docs/repowiki/05-daemon.md（会话管理章节）
    ✓ docs/ai/已知坑.md 会话四件套
    ✗ docs/ai/recipes/run-e2e.md 会话验收
```

**`--check` 的判定**（退出码：0 = 通过或被合法豁免，1 = 缺文档或豁免理由不合法）：

- 默认：规则列出的每篇文档都必须在本次 diff 里（删除不算同步）。
- `anyOf: true`：多篇候选文档改任意一篇即可（脚本说明、目录结构文档这类分散在多处的知识）。
- 动态文档：`preset` 规则从新增行里取预设名，按 `接入-<name>.md` 推导期望文档，比较时大小写与连字符不敏感。

**豁免**：提交信息或 PR 描述写 `Docs-Impact: none — <理由>`；pre-commit 没有提交信息，读环境变量 `DOCS_IMPACT`，值可以只写 `none — Pure refactor`。允许的理由只有三种：

| 理由 | 含义 |
|---|---|
| `Pure refactor` | 纯重构，行为不变 |
| `Comment only` | 只改注释 |
| `Test update` | 只改测试 |

**为什么留豁免**：没有出口的检查会被 `git commit --no-verify` 绕过，机制等于零。把出口放在明面上，并限制理由白名单，比逼人偷偷绕过好。

### 3.2 `doc-impact.rules.mjs`：规则表

每条规则的字段：

| 字段 | 含义 |
|---|---|
| `id` | 规则名，出现在输出里 |
| `why` | 一句话：这条规则防的是什么 |
| `files` | 可选；限定只看这些路径的 diff，不写则看全部 |
| `trigger(diffLines)` | 判断是否触发 |
| `docs` | 触发后必须同步的文档（路径 + 章节说明） |
| `anyOf` | 可选；`docs` 改为「改任意一篇即可」 |
| `dynamicDoc` | 可选；从新增行提取预设名，动态推导 `docs/接入方案/接入-<name>.md` |
| `note` | 可选；`--check` 失败时额外打印的提示 |

规则表是**封闭清单**：AI 不需要自己回忆「可能受影响的文档有哪些」，查表即可。当前 12 条见 §3.3。

### 3.3 12 条规则

| id | 触发条件 | 为什么要管 | 触发后要改的文档 |
|---|---|---|---|
| `env-var` | 新增行里出现 `process.env.XXX`（限 `+packages/`） | 新增环境变量最容易只写代码不写文档 | 速查 §6/§7、README 环境变量表、随包 README、repowiki/09、`docs/ai/已知坑.md` |
| `preset` | `brain-presets.ts` 新增 `name: "xxx"` | 接新 agent 必须同时产出接入文档与索引 | `接入-xxx.md`（新建）、接入其它-ACP-Agent.md §5、`docs/ai/已知坑.md`、docs/README.md、llms.txt、ai/README.md |
| `cli-command` | `cli/manage.ts` 新增 `case "xxx"`，或 `ipc/chat-command-specs.ts` 新增条目 | 命令是用户直接调用的接口 | README 命令速览、新手教程、速查、随包 README、AGENTS.md §3 |
| `data-file` | `store/*.ts` 或 `*-store.ts` 改结构/文件名 | 数据文件格式影响升级兼容与排障 | repowiki/08、速查「数据目录」、AGENTS.md §4 |
| `behavior-session` | `session-manager.ts`、`session-registry.ts`、`session-map.ts`、`handoff.ts` 有逻辑改动 | 会话五指令、严格恢复、登记表语义是用户可见行为 | repowiki/05、`docs/ai/已知坑.md`「会话四件套」、run-e2e 会话验收 |
| `behavior-worker` | `worker-pool.ts`、`worker-acp.ts`、`task-manager.ts` 有逻辑改动 | 多任务、编号寻址、进程池回收都是用户可见行为 | repowiki/07、`docs/ai/已知坑.md`「多任务并行/寻址」、run-e2e 任务验收 |
| `behavior-brain` | `acp-brain.ts`、`acp-connection.ts`、`acp-reverse.ts`、`brain-switch.ts`、`acp-quiet.ts` 有逻辑改动 | 协议层变化影响所有 agent 的接入结论 | repowiki/06、`docs/ai/已知坑.md`「热切换」、run-e2e brain 验收 |
| `brain-split` | `agent-slot.ts`、`brain-config.ts`、`brain-state.ts`、`brain-check.ts` 有逻辑改动 | 大脑选择/持久化/预检影响 `wemind brain` 的全部说明 | repowiki/06「大脑配置」、AGENTS.md §4.12 |
| `script` | `scripts/*.ps1` 或 `scripts/*.mjs` 新增/改语义 | 脚本的用法写在文档里 | repowiki/11、repowiki/10 或 daemon-常驻原理、AGENTS.md §3（任一） |
| `new-doc` | `docs/**/*.md` 新增 | 新文档不进总索引等于不存在 | docs/README.md、llms.txt |
| `release` | `packages/*/package.json` 的版本号变化 | 版本号是发布流程的单一来源 | `docs/发布与变更记录/CHANGELOG.md`、如何发布新版本.md |
| `restructure` | `src/` 下出现重命名（git rename 检测），或一次改动涉及 5 个以上文件的增删 | 目录重构会让大量文档里的路径引用失效 | AGENTS.md §2、`docs/ai/代码地图.md`、`docs/ai/README.md`、repowiki/02（至少一处），并对照《源码目录分层设计》§9 的完整清单 |

### 3.4 为什么 `restructure` 单独设计

目录重构的 diff 通常长这样：

```text
D packages/wechat-daemon/src/acp-brain.ts
A packages/wechat-daemon/src/acp/acp-brain.ts
```

普通规则只看「新增行里有没有关键词」，这种移动它不会触发。所以 `restructure` 判断两件事：

1. `git diff --name-status -M` 出现 `R`（git 自己识别出的重命名/移动）；
2. `src/` 下「删除 + 新增」文件合计超过 5 个（拆分、合并、目录迁移）。

触发后**至少改一处**目录结构文档（`anyOf`），并打印[源码目录分层设计](源码目录分层设计.md) §9 的完整清单提醒逐项核对。历史快照类文档（如 2026-11-02 审查快照、CHANGELOG）按约定只加「当时路径」说明，不改正文，因此不强制全部改完。

### 3.5 `check-agent-docs.mjs`：接入文档完整性

**解决的问题**：接新 agent 时文档「写了」，但缺「已知限制」或「待实测」，读者拿不到关键信息。

对 `ACP_AGENT_PRESETS` 里的每个预设（当前 9 个），检查：

1. `docs/接入方案/接入-<名字>.md` 存在（先按文件名归一化匹配，`claude-code` ↔ `接入-ClaudeCode.md`；文件名对不上才退回正文唯一命中，避免通用文档抢走多个预设）；
2. 头部有「最后核对」「实测环境」「状态」三个字段；
3. 有五类二级标题：安装/准备、预设/沙箱、探针/实测、限制（或风险）、验证/复现/验收；
4. 有独立的 `## 待实测` 小节（没有待测项就写「无」；允许 `## 7. 待实测` 这类编号前缀）；
5. 预设名或文档名出现在四处索引：`接入其它-ACP-Agent.md` §5、`docs/ai/已知坑.md`、`docs/README.md`、`llms.txt`。

**没有白名单**。9 篇文档的缺口在 2026-11-06 一次补齐，之后新增预设必须一开始就满足。

### 3.6 `gen-docs-tables.mjs`：表格生成

**解决的问题**：同一张表写在多处，改一处不会报错，只有人肉比对才发现。

只生成三张能从代码枚举的表，不生成说明文字：

| 表 | 数据来源 | 写入位置 |
|---|---|---|
| 环境变量 | `packages/*/src/**/*.ts` 的 `process.env.X`（排除测试与系统变量） | `docs/repowiki/09-配置项与环境变量.md`、`docs/使用指南/速查-数据目录与环境变量.md` |
| 内置预设 | `brain-presets.ts` 的 `ACP_AGENT_PRESETS` 键名与启动参数 | `docs/接入方案/接入其它-ACP-Agent.md` §5 |
| CLI 命令 | `cli/manage.ts` 等入口的 `case` 分支 + `ipc/chat-command-specs.ts` 命令表 | `README.md` 的「命令一览」 |

用法：

```bash
npm run docs:tables           # 重新生成标记块里的表格（会改文件）
npm run docs:tables:check     # 只比对，不一致就 exit 1（CI 用）
```

标记块之外的文字不动：

```markdown
<!-- BEGIN:auto env-vars -->
| 变量 | 默认 | 出处 |
|:---|:---|:---|
| `WEMIND_HOME` | `~/.wemind` | `packages/wechat-daemon/src/agents/brain-config.ts:12` |
<!-- END:auto env-vars -->
```

**表格格式约定**：

- 表头左对齐（`|:---|`），不居中——中文表格居中后列宽跳动，难扫读；
- 变量名、命令名、默认值一律用反引号，可复制；
- 没有默认值的写 `—`，不混用「无」「N/A」；
- 布尔开关的默认写「未设置（关闭）」；
- 按变量名 ASCII 升序，保证生成结果稳定、diff 干净；
- 只生成可枚举的列，说明性文字留在表外由人写——**散文靠人写，表格靠机器**。

## 4. 运行方式

| 位置 | 跑什么 | 约束 |
|---|---|---|
| `npm run verify` | 三个守卫 + 链接检查（在测试之后） | 可以慢一点 |
| CI `build-test` | 三个守卫 + 链接检查，`ubuntu` 与 `windows` 两个平台 | checkout 需要 `fetch-depth: 0` |
| `.githooks/pre-commit` | `format:check`、`doc-impact --check --staged`、`check-agent-docs` | 必须 1–2 秒内；慢检查会被 `--no-verify` 跳过 |
| PR 模板 | 文档影响与验证项检查单 | 人工兜底，不替代脚本 |

豁免的入口差异：CI 读 PR 描述或提交信息里的 `Docs-Impact` trailer；pre-commit 读 `DOCS_IMPACT` 环境变量。`docs:tables` 的生成动作不进钩子——生成会改工作区，必须人工确认 diff。

## 6. 已知边界

- **只查有没有改，不查改得对不对**：`doc-impact` 不能判断新增段落是否准确，内容质量仍靠评审。
- **豁免可以被滥用**：理由白名单挡住「时间不够」，挡不住有人写 `Pure refactor` 蒙混。这是有意的取舍——宁可留明面出口，也不让人用 `--no-verify`。
- **`check-agent-docs` 只认内置预设**：用户自己接的外部 agent 不在检查范围。
- **表格只覆盖标记块**：块外手写的同类信息仍可能过期，需要评审。
- **未覆盖的约束**：`AGENTS.md` §4 中 §4.9 密钥、§4.10 注释换行、§4.14 用 agent 不改造、§4.16 worktree 位置只能靠评审；「有没有为这次行为写测试」同样没有自动检查。
- **删除方向没有检查**：`env-var` / `preset` 只看新增行；删掉一个环境变量或预设时不会触发规则，被删预设的接入文档也不会被 `check-agent-docs` 发现（它只遍历现存预设）。删除时请手动同步文档与索引。
- **pre-commit 只读暂存区**：未 `git add` 的修改不参与判断；`check-agent-docs` 读工作区。两者口径略有差异，提交前跑一次 `npm run verify` 最稳。

## 7. 维护指南

### 7.1 新增一条 `doc-impact` 规则

1. 在 `scripts/doc-impact.rules.mjs` 的 `RULES` 末尾加一条：`id` / `why` / `trigger` / `docs`，按需加 `files`、`anyOf`、`dynamicDoc`、`note`。
2. 在 `scripts/doc-guards.test.mjs` 加「命中 / 不命中」两个方向的最小用例。
3. 更新本文件 §3.3 的规则表，并在 `docs/repowiki/11-开发指南.md` 的守卫小节确认无需补充。
4. 跑 `npm run doc-impact` 看输出是否可读。

### 7.2 新增一张自动生成的表

1. 在 `scripts/gen-docs-tables.mjs` 增加收集与渲染函数，并在 `TARGETS` 注册目标文件。
2. 在目标文档里放 `<!-- BEGIN:auto <id> -->` / `<!-- END:auto <id> -->` 标记块。
3. 加渲染与 `replaceBlock` 的用例，跑 `npm run docs:tables` 生成一次并检查 diff。
4. 更新本文件 §3.6 与 `repowiki/11`。

### 7.3 修改接入文档的固定结构

改 `scripts/check-agent-docs.mjs` 顶部的 `HEADER_FIELDS` / `REQUIRED_SECTIONS` / `INDEX_FILES`，同步改 `docs/ai/recipes/add-acp-agent.md` §0.5 的产出物清单，并跑一次全量检查确认 9 篇都还通过。

任何改动完成后跑 `npm run verify`，并更新本文头部与相关索引的「最后核对」日期。
