# 使用指南：远程任务（worker）

> **适用版本**：WeMind 1.2.0 ｜ **最后核对**：2026-10-28
>
> 让**漫长任务在后台受控运行**，在它「需要你决策」（列了方案让你选）或「中断」时通知你，你回一句它就接着干。可以**同时开多条**（默认上限 3，各自一个独立进程）。
> 两个入口管同一批任务：**微信**（人离开电脑时）＋ **本地终端**（人在电脑前时）。
> 背后原理见 [方案C-MVP-远程human-in-the-loop.md](方案C-MVP-远程human-in-the-loop.md)、[方案C-受控ACP工作机设计.md](方案C-受控ACP工作机设计.md)、[本地双入口-命令派发与查看回复.md](本地双入口-命令派发与查看回复.md)。

---

## 0. 前提

> `wemind` 是已发布的命令（`npm i -g @wemind/cli`，包名与命令名不同，临时用写 `npx -y @wemind/cli …`）；仍从源码跑时，把下文所有 `wemind` 替换为 `node packages/wechat-daemon/dist/cli.js`（如 `node packages/wechat-daemon/dist/cli.js list`）。

- daemon 正在运行（且已扫码登录某账号）。检查：
  ```bash
  wemind list   # 看到「运行中(pid …)」即可
  ```
- 没在跑就启动：`wemind start [<key|label>]`（省略 = 默认账号；或 `scripts/run-all-daemons.ps1` 全部账号）。

## 1. 一分钟上手

### 在电脑前（本地终端）

```bash
# 派发任务：在哪个项目目录就让它在哪跑（--cwd 默认取当前终端目录）
wemind task "核实这篇文章每个论断的真假，先列出你打算查证的点让我确认" --cwd D:\Product\xxx

# 指定用哪个 agent 跑这条任务（不带 --agent 就用「默认任务大脑」）
wemind task "整理本周周报" --agent kiro

# 看进展（状态 + 轮次 + 最近输出，不依赖微信）
wemind task-status      # 有任务表时与 task-list 同源（同一份列表）；表空/不存在才退回读单个记录
wemind task-list        # 全部任务：编号 / agent / 状态 / 轮次 / 已运行 / 最近输出

# 回复它的提问 / 让它继续 / 结束（只有一条任务时可省略编号）
wemind task-reply "第 2 点不用查，其它都查"
wemind task-reply 2 "第 2 点不用查，其它都查"
wemind task-reply 继续
wemind task-stop 2      # 结束 2 号；不带编号只在恰好一条活跃任务时生效（多条会回一份清单让你指明编号），task-stop all 结束全部
```

### 在微信

```
任务：核实这篇文章每个论断的真假，先列出你打算查证的点让我确认
任务 qoder：顺便把这篇文章翻成中文          ← 冒号前是已知 agent 名 = 指定 agent，总是新开一条
（它停下来问你时）直接回： 第 2 点不用查，其它都查      ← 只有一条任务时，无前缀即发给它
#2 第 2 点不用查                              ← 多条任务里指明编号（只有一条在等你回复时可直接回）
问大脑 现在几点                                        ← worker 跑着时想顺便问大脑别的
任务列表                                                ← 编号 + agent + 状态
结束任务 2 / 结束全部任务
```

## 2. 两个入口对照

| 操作 | 微信 | 本地终端（`wemind`） |
|---|---|---|
| **派发** | `任务：<描述>` 或 `>「描述」`（用默认任务大脑）；`任务 <agent 名>：<描述>` 指定 agent（**总是新开一条**；不影响默认任务大脑） | `task "<描述>" [--cwd 目录] [--agent <名字>] [<key\|label>]` |
| **回复 / 续跑** | 只有一条任务时**直接回**；多条时 `#<编号> 正文`（或 `/reply <编号> 正文`） | `task-reply <编号> "…"`（也可写成 `task-reply "#2 继续"`；不给编号 = 唯一那条） |
| **看状态** | worker 推来的 `🤖【任务】…` 消息；或 `任务列表` / `/tasks` | `task-status` / `task-list`（有任务表时两者是同源的一份列表；表空/不存在才退回读单个记录） |
| **结束** | `结束任务 [编号]` / `结束全部任务` | `task-stop [编号\|全部]` |
| **默认任务大脑** | `切换任务大脑 <agent 名>` / `/worker <agent 名>` / `/ai task <agent 名>`（不带名只回「当前默认任务大脑：X」；看可选 agent 用 `AI` / `/ai`） | `wemind brain switch <agent 名> --worker` |
| **临时问大脑** | `问大脑 <内容>`（worker 等你时也能插话） | 大脑对话不走这里——直接开你自己的 kiro，或用微信 |

> **核心**：两个入口操作的是**同一批任务**。可以本地派发、离开后用微信接着管；也可以微信派发、回到电脑用 `task-list` 看。**任务编号按人递增、不复用**（任务 1、任务 2…），跨 daemon 重启也不归零——所以「任务 2」在对话里永远指同一条。

## 3. 典型场景

- **A. 电脑前开 + 离开遥控（最常用）**：终端 `task "..." --cwd 项目目录` 派发（长描述、指定项目都方便）→ `task-status` 看头几步对不对 → 放心离开 → 之后 worker 卡点会推微信，你在微信回一句（多条任务时带 `#编号`）续跑。
- **B. 纯本地**：不想碰微信、专注电脑工作，全程终端 `task` / `task-list` / `task-reply` / `task-stop`。
- **C. 纯微信远程**：人不在电脑，全程微信 `任务：` → 回复（`#编号`）→ `结束任务`。
- **D. 多任务并行**：微信 `任务 kiro：整理周报` + `任务 opencode：跑测试` 两条同时开，各自独立进程、独立进度；回话时用 `#1` / `#2` 区分。默认最多同时 3 条（`WEMIND_MAX_WORKERS`）。

---

## 4. worker 能干什么

- 跑在你指定的工作目录（`--cwd`），**继承所用 agent 的沙箱**——以 kiro 为例：继承 `~/.kiro` 的全部 MCP（除 `wechat`）＋ 记忆 / 技能 / 模型，能力与你本地的 kiro 一致（读写文件、联网、调用工具都行）；换别的 agent 时按它的沙箱规则（见各接入文档）。
- 适合**漫长任务**（联网核实、批量分析、构建、长文处理等）：后台跑、卡点找你，不占用你的电脑或当前会话。
- **每条任务一条独立 ACP 连接**：互不干扰，一条卡住/结束不影响其它；任务跑完**留着复用**（不杀），空闲超 5 分钟才回收。两个例外：正在跑的任务被 `结束任务` / `task-stop` 时是**直接杀掉**（ACP 回合没法优雅取消，进程进程不保留）；停在「等你回复」的任务会一直占着那条连接，不计入空闲进程、也不受 5 分钟回收影响。
- 每轮输出带 `🤖【任务】` 标记；跑一轮期间微信会显示「正在输入中」。

## 5. 注意事项 / FAQ

- **daemon 必须在运行**：派发/回复/结束这类命令会先检查，没跑会提示先 `start`。
- **本地派发时微信收不到推送（`ret=-2`）？** 最常见的是 daemon 刚重启、你还没在微信和它说过话：此时缓存的 `context_token` 还是上次运行的，服务端不认，worker 的输出推微信会被拒。现在这种推送会**先挂起**（`daemon.log` 里能看到「`send -2（旧 token）→ 挂起`」），**你在微信给 bot 发任意一条消息**（带来新 token）后自动按原顺序补发（日志「`新 token 已到 → 补发挂起消息 N 条`」），不用重派任务。挂起队列只在内存里：daemon 再重启一次就丢，但 `task-status` / `task-list` 照样看得到结果。
- **多任务默认上限 3**（`WEMIND_MAX_WORKERS`）：满了再派发会被**直接拒绝**并提示（不排队，避免任务悄悄等着）。任务跑完**进程留着复用**（不杀），空闲连接超 `WEMIND_WORKER_REAP_MS`（默认 5 分钟）回收；但**正在跑的任务被结束时是直接杀掉**（进程不保留），停在「等你回复」的任务则一直占着连接；`wemind stop` / daemon 退出会一次杀光池里全部 worker。
- **多条任务并存时必须带编号**：微信 `#2 正文` / `/reply 2 正文`，CLI `task-reply 2 "…"`。不带编号时 daemon 会回一份清单（编号 + agent + 状态）让你带编号重发。只有一条任务时仍可免编号直接回；多条里**只有一条在等你回复**时，无编号消息也喂给它（「谁在等就喂谁」优先于「必须带编号」）。
- **派发时选 agent**：微信 `任务 <agent 名>：正文`（冒号前必须是不带空格的**已知 agent 名**才算指定；`任务 明天：去买菜` 不当成指定 agent，整串仍是派给任务侧的正文——要只跟大脑说话用 `问大脑 …`）→ 永远新开一条任务；CLI `wemind task "…" --agent <名字>`——这个指定**只对这条任务生效**，不改默认任务大脑。不指定就用**默认任务大脑**（微信 `切换任务大脑 <agent 名>`、CLI `wemind brain switch <agent 名> --worker`）——它**只存在进程内、不写配置文件**，daemon 重启后回到配置里的默认值（答复里会说明）。
- **它停下来 ≠ 卡住**：worker 每跑完一轮会停下等你（waiting），这是设计；你不回它就一直等，回了才续跑。
- **中断恢复**：worker 崩溃/超时会提示「回复『继续』恢复」，回 `继续` 会尝试从上次会话续上（`session/load`，不支持时 `session/resume`）。**daemon 重启**后未完成的任务则标为**「已中断」**（在 `任务列表` 可见），**不会**自动跑起来；你回 `继续`（多条时 `#<编号> 继续`）才拉进程 + 按该 agent 的能力试 `session/load` → `session/resume` 续跑。**接不上会明确说「这次接不上」**，不会假装成功——而且它**不会**劝你「把进展重述一遍」：重述也是走同一条恢复路径、还是接不上。真想从这条任务重来，就 `结束任务 <编号>` 后重新派一条（把进展写进新任务里）；续跑前会提示「半截回合的副作用可能已经发生，注意核对」。
- **模型/账号侧出错（如余额不足）的任务不会抢你的消息**：这类错误重试也不会好，所以任务一轮失败就直接转**「已中断」**（不再停在「等你回复」——那种状态会把你之后的日常消息都吞进去、只是再白失败一轮）。提示里会说清是哪类问题（额度/余额不足 · 密钥/鉴权有问题 · 计费问题 · 模型不可用），你处理完账号后回 `继续`（多条时 `#<编号> 继续`）从中断处续跑。限流（429）与超时**不在此列**，仍按原样停在「等你回复」。
- **升级 CLI 后重启一次 daemon**：换大脑、开新会话/恢复会话这类命令**必须由 daemon 执行**（经控制桥）；daemon 还在跑旧版本时，它们会在发出前拒绝并提示 `wemind stop <账号> && wemind start <账号>`。**本来就是读写登记表**的 `session list`/`rename`/`delete` 照常能用（`list` 会多一行说明：它是按「下次会用的那个大脑」列的）。任务侧不受影响：`task-list` / `task-status` 直接读文件（从不过桥；daemon 没跑时会注明显示的「运行中」只是上次留下的记录）。
- **安全**：**内置预设默认免审批**（kiro `--trust-all-tools`、qoder `--yolo`、gemini yolo、opencode 沙箱 `permission: allow`、DSH `danger-full-access`、claude-code `bypassPermissions`、codex `agent-full-access`），能在指定目录全权操作（含 shell/写文件）。微信侧本来只有登录者能发消息（平台限制），另有 allowFrom 登录者白名单兜底（默认只放行登录者）；本地侧 = 能在你电脑敲命令的人（机主）。控制桥只接受**agent 名与纯数据**（不接受自定义二进制路径/参数），伪造请求最坏也只能「选一个已安装的 agent」。
- **DeepSeek（DSH）大脑的沙箱边界**：微信派发的 worker 工作目录默认是**用户主目录**，DSH 的 `workspace-write` 只允许写工作区+临时目录——跨盘/工作区外的写入会被拒，模型申请提权时默认**拒绝**（`WEMIND_ACP_AUTO_ALLOW=1` 才放行）。跨盘任务建议本地 `task --cwd <目标目录>` 派发或设 `WEMIND_WORKER_CWD`；另注意 cwd=主目录时 `TEMP` 在工作区内，DSH 的 pwsh 工具会报 `Windows ACL temp root must be outside the workspace`。

## 6. 相关环境变量（可选调）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WEMIND_WORKER_CWD` | 用户主目录 | worker 默认工作目录（本地 `task --cwd` 会覆盖） |
| `WEMIND_MAX_WORKERS` | 3 | 同时运行的**任务**数上限（超了直接拒绝派发，不排队） |
| `WEMIND_IDLE_MAX` | 2 | 池里保留的空闲 worker 连接数上限（从最旧的开始回收） |
| `WEMIND_WORKER_REAP_MS` | 300000（5min） | 空闲超多久回收 worker 连接 |
| `WEMIND_WORKER_IDLE_MS` / `_CAP_MS` / `_FIRST_FRAME_MS` | 180000 / 1800000 / 30000 | worker 单轮空闲 / 硬上限（到点就放弃）/ 首帧超时 |
| `WEMIND_WORKER_PROGRESS` | `0` | 是否推送全程文字进度（默认安静；`1` 开启） |
| `WEMIND_TASK_SCAN_MS` | 1000 | daemon 扫描本地命令收件箱的间隔 |
| `WEMIND_WORKER_MCP_EXCLUDE` | `wechat` | worker 不继承的 MCP（`wechat` 强制排除防它把消息发回自己） |
