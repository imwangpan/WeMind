# 9. 配置项与环境变量

> 上一页：[8. 数据存储与多账号](08-数据存储与多账号.md) ｜ 下一页：[10. 部署与运维](10-部署与运维.md)
>
> **最后核对**：2026-11-12

WeMind 的可配置项几乎全部通过环境变量暴露，**改配置无需动代码**。本章按用途分类汇总。所有变量都有合理默认值，开箱即用。

> ⚠️ 环境变量属于**进程**，不属于账号：同一个终端（或同一个服务管理器环境）启动的多个 daemon 会继承同一组值。`WEMIND_BRAIN` 会同时压过每个账号的 `brain.json`，API key 所有账号共用，`WEMIND_MAX_WORKERS` 是**每个 daemon 各自**的上限（N 个账号合计可达 N × 值）。多账号自启脚本支持 `WEMIND_MAX_WORKERS_TOTAL`：`run-all-daemons.ps1` 按账号数均分后给每个子进程注入 `WEMIND_MAX_WORKERS`（至少 1，只覆盖它拉起的 daemon）。要按账号取不同值，就分开环境启动；持久的大脑选择用账号级 `wemind brain set`（写 `brain.json`）。
>
> `daemon.log` 会轮转：`WEMIND_LOG_MAX_MB`（默认 10）是单文件上限，`WEMIND_LOG_KEEP`（默认 3）是保留份数（`daemon.log.1` 最新，`0` = 不留历史）。内置 watchdog 在运行中按块轮转，`run-daemon.ps1 -Mode shell` 在每次重拉前轮转；pm2 runner 交给 `pm2-logrotate`（见 §9.7 与 [10. 部署与运维](10-部署与运维.md) 的日志一节）。

### Agent 选择与接入

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_BRAIN` | `auto` | 选 ACP agent（`kiro`/`opencode`/`gemini`/`deepseek`/`qoder`/`cline`/`claude-code`/`codex`/`pi`/`copilot`；`auto`=只探测 6 个原生预设）。**优先级最高，覆盖账号 `brain.json`** |
| `WEMIND_BRAIN_BIN` | 自动解析 | 覆盖二进制（绝对路径或 PATH 上的名字） |
| `WEMIND_BRAIN_ARGS` | 内置默认值 | 覆盖进入 ACP 模式的启动参数（空格分隔、**整段替换**） |
| `WEMIND_BRAIN_EXTRA_ARGS` | 无 | 追加启动参数（空格分隔，拼在预设/覆盖参数之后；只加开关时用它） |
| `WEMIND_BRAIN_HOME_ENV` | 内置默认值 | 覆盖「配置目录环境变量名」（仅对该 Agent 生效：`real`/`mirror` 指向 `agent-view/brain/<agent>`，`sandbox` 指向账号沙箱；没有 `homeEnvVar` 的 Agent 不使用） |
| `WEMIND_BRAIN_SHELL` | 该 agent 预设的 `shell`（10 个预设里 8 个是 `true`） | 是否经 shell 启动（npx/.cmd 类在 Windows 需要）。**不是**全局 `false`——不设时按所选 agent 的预设值 |
| `KIRO_CLI_BIN` | — | 旧的 kiro 专用二进制覆盖（仍兼容） |

`copilot` 预设仅在 Copilot CLI 子进程中设置 `COPILOT_HOME`，指向当前角色的配置视图/沙箱；它不是建议用户全局设置的 daemon 环境变量。

上表是**环境变量一次性覆盖**（最高优先级）。**持久选择**用账号级 `<数据目录>/brain.json`，正门是 `wemind brain set`：

```bash
wemind brain set <agent 名|auto> [--bin X] [--args "…"] [--extra-args "…"] [--shell|--no-shell] [--model X|auto] [--restart]
```

**`brain set` 的行为**：

- **读-改-写**：不再整体覆盖文件，`worker` / `presets` 段会保留。
- **`auto` 不绑定具体 agent**：不能配 `--bin` / `--args` / `--extra-args` / `--shell` / `--model`（否则会下发给探测到的任意 agent）。
- **`--args ""` / `--extra-args ""` 是显式清空**（顶层与 `presets[agent]` 一起清，不会被旧值盖回来）。
- **纯 agent 名 = 当场换大脑**：不带 `--bin` / `--args` / `--shell` / `--model` / `--restart`，且 daemon 在跑并**认控制桥**（`control-out/.bridge` 的 pid 对得上）时，等价于 `brain switch`——先启动新大脑、成功才写入磁盘，失败退回。
- **带启动细节只写盘**：带 `--bin` / `--args` / `--shell` / `--model` 时退化为「只写入磁盘」（控制桥刻意不接受这些字段，是安全边界）；其中 `--bin` / `--args` / `--model` 可由随后的 `wemind brain switch <同名 agent>` 当场应用，否则重启 daemon。

**`brain.json` 的结构**（除 `agent` 外还有两个可选段）：

| 段 | 内容 |
|---|---|
| `presets` | 按 agent 名保存 `--bin` / `--args` / `--shell` / `homeEnvVar` / `model` 这类覆盖；换 agent 时旧覆盖会迁移进来，避免「切走再切回丢 `--bin`」 |
| `worker` | 默认任务大脑：`{agent, bin?, args?, shell?, homeEnvVar?, model?}`（取值优先级见 9.6） |

**`model` 的语义**（格式 `["provider 路由","模型名"]`，值由各 agent 自己的 provider 配置决定；DSH 的旧例子 `'["deepseek-account","deepseek-flash"]'` 在 rc.3 已失效）：

- 会话建立后经 `session/set_config_option` 下发一次；显式覆盖以它为准。
- 解析优先级：**本段 > `presets[agent 名]` > 真实 profile 的默认 > 预设兜底**。
- 「真实 profile 的默认」由 `profile-model.ts` 读：**优先用户自己写的 `- id: acp`，否则 `agent-default-model`**（`- id: acp` 由用户维护，缺了 `wemind brain` 会给片段）。
- 写 `auto` / `default` = **跟随真实 profile 的默认**（DSH 读 `~/.dsh/profiles/acp/cordis.patch.yml`，具体值由用户的 DSH 配置决定）；读不到就**不下发**——预设值 `["deepseek-account","deepseek-flash"]` 只在**完全没配** `model` 时兜底（rc.3 已失效，只记 WARN），写 `auto` / `default` 不会用它。

未配置时默认 `auto`（按 `opencode → cline → qoder → gemini → deepseek → kiro` 探测第一个已安装者）。daemon **启动即校验**大脑，不可用会 `FATAL` 退出（退出码 78）。

> **内置预设默认免审批**（2026-10-30 起；kiro v3 支持于 2026-11-03 补上）。每个 agent 用**它自己的**开关，不是统一 flag：
>
> | agent | 免审批方式 |
> |---|---|
> | kiro v2 | `--trust-all-tools` |
> | kiro v3 | 不用上面那个参数（按 `--agent-engine` / 真实 `settings/cli.json` 的 `acp.agentEngine` / CLI 主版本 ≥3 识别——后两项为兜底；`acp --help` 说两者都没设时默认 v2，CLI ≥3 默认 v3 为假设/待实测）；写配置视图/沙箱的 `settings/permissions.yaml` allow-all，真实已有则原样保留 |
> | gemini | `--approval-mode yolo --skip-trust` |
> | qoder | `--yolo` |
> | cline | `--auto-approve true` |
> | opencode | 配置视图/沙箱 `opencode.json` 的 `"permission": "allow"` |
> | DSH | 预设 `envDefaults: DSH_PERMISSION_MODE=danger-full-access` |
> | claude-code / codex | 会话建立后 `session/set_mode`（`bypassPermissions` / `agent-full-access`） |
> | pi | 无需任何开关（官方默认不逐次审批） |
>
> **想收紧时**：`DSH_PERMISSION_MODE` / `INITIAL_AGENT_MODE` 是 `envDefaults`（父进程已设同名变量时不覆盖，日志记 `env defaults kept from parent: …`）；`WEMIND_ACP_SESSION_MODE=0/false/off/no` 关掉 `set_mode`；`--args` 仍可整段替换启动参数。`wemind brain` 的「生效」行会显示 `session_mode=`。WeMind 侧权限应答器仍默认拒绝 `session/request_permission`，`WEMIND_ACP_AUTO_ALLOW=1` 才逐次放行。

### 运行时切换与会话

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_SWITCH_DRAIN_MS` | 30000 | 热切换时等在跑回合结束的上限（超时 = 诚实失败，不砍回合） |
| `WEMIND_SWITCH_TIMEOUT_MS` | 120000 | 启动新大脑（`initialize` + 会话）硬上限 |
| `WEMIND_CONTROL_TIMEOUT_MS` | 30000 | CLI 等 daemon 回话的上限；`brain switch` 会自动放大到 `启动新大脑 + 等在途回合结束 + 15s`；`brain.handoff` 按回合硬上限放大（默认 915s） |
| `WEMIND_HANDOFF_TTL_MS` | 86400000 | 交接摘要（`handoff.json`）的有效期，默认 24h；切到别的大脑后下一条用户消息作为前缀带上一次，答成才清除 |
| `WEMIND_SESSION_LOG_MAX` | 50 | 会话登记表每个「登录者 · 大脑」保留的条数上限，超出先淘汰「未命名且最旧」的（`session-registry.ts`） |
| `WEMIND_SESSION_PAGE_SIZE` | 10 | `wemind session list` / 微信「会话列表」的每页条数（`--page N` 翻页） |

> 运行时切换入口：微信 `切换大脑 [名]` / `/ai brain` / `/brain`，CLI `wemind brain switch <agent 名|auto>`（加 `--worker` 只设**默认任务大脑**：**本次运行内一直生效**、不写 `brain.json`，重启回到配置值）。`WEMIND_BRAIN` 仍是优先级最高的一次性覆盖：命令式切换在进程内生效并写入磁盘，但重启后 env 还在就会回到 env 指的大脑（答复里有警告，别写进 profile）。

## 9.8 常见配置场景

**放宽超长任务超时**（对话大脑）：

```
WECHAT_BRAIN_CAP_MS=1800000   # 30min
WECHAT_BRAIN_IDLE_MS=180000   # 3min
```

**切换到 Gemini CLI 当大脑**（推荐写入磁盘持久）：

```powershell
wemind brain set gemini --restart   # 写入账号 brain.json 并重启 daemon
```

```bash
# 或一次性覆盖（仅本次启动的 daemon）：WEMIND_BRAIN=gemini
```

**用绝对路径指定 agent 二进制**（绕开 PATH/shim）：

```powershell
wemind brain set kiro --bin "C:\Users\me\AppData\Local\Kiro-Cli\kiro-cli.exe"
# 或一次性覆盖：WEMIND_BRAIN_BIN=C:\Users\me\AppData\Local\Kiro-Cli\kiro-cli.exe
```

**多账号常驻**（每账号一个进程，目录由**账号 key** 决定）：

```
WECHAT_ACCOUNT=<accounts.json 里的 key>    # 账号 A
WECHAT_ACCOUNT=<另一个 key>               # 账号 B（不同进程）
```

> ⚠️ **`WECHAT_ACCOUNT` 不能随便起名**：key 由 `wemind login` 从 botId 派生并登记进 `<根>/accounts.json`（`wemind list` 可查）。写成 `work` / `home` 这类任意名字会指向一个**未登记的空目录**，daemon 启动即「未登录」。要么用已登记的 key，要么直接给 `WECHAT_DATA_DIR` 绝对路径。

**热切换大脑（不用重启 daemon）**：

```powershell
wemind brain switch gemini              # 走控制桥热切换；微信里也可发「切换大脑 gemini」
wemind brain switch gemini --worker     # 只把「默认任务大脑」设为 gemini（本次运行内一直生效，不写 brain.json）
```

等回合结束的上限 `WEMIND_SWITCH_DRAIN_MS`、新大脑启动的上限 `WEMIND_SWITCH_TIMEOUT_MS` 可调；带 `--bin` / `--args` / `--extra-args` / `--shell` / `--model` 的 `wemind brain set` 例外，**命令本身**只写入磁盘（控制桥不接受这些字段）——其中 `--bin`/`--args`/`--extra-args`/`--model` 可紧接着执行 `wemind brain switch <同名 agent>` 当场应用（`sameAgent()` 按 name/bin/args/model 判是不是同一个），`--shell` 不在判据里、只能重启 daemon（daemon 不认桥时都需重启，答复会写明）。

**调任务并发与进程池回收**：

```
WEMIND_MAX_WORKERS=6           # 同时最多 6 个任务
WEMIND_IDLE_MAX=4              # 池中最多保留 4 个空闲 worker
WEMIND_WORKER_REAP_MS=600000   # 空闲 worker 10 分钟回收（默认 5 分钟）
```

**给任务单独指定大脑**（对话仍走原大脑）：

```
WEMIND_WORKER_BRAIN=deepseek   # 或写进 brain.json 的 worker 段；CLI 亦可 wemind brain switch deepseek --worker
```

> 这些变量需对 **daemon 进程**生效。Windows 计划任务继承登录用户的环境（`setx` 设置的值可用）；Linux systemd / macOS launchd **不读取 shell 配置**，要写进服务单元（systemd `Environment=` / `EnvironmentFile=`，launchd `EnvironmentVariables`），`wemind autostart install` 只会带 `WECHAT_ACCOUNT`、`WECHAT_DATA_DIR=`（空值覆盖）、`WEMIND_HOME`（若设置）和 `PATH`。只在当前终端临时设的值不会带过去。用 `scripts/run-daemon.ps1` / pm2 启动时在脚本或计划任务环境中设置（默认 cli 薄壳会像 `wemind start` 一样丢弃 `WECHAT_DATA_DIR`，只有 `-Mode shell` 直跑 daemon 时该变量才覆盖数据目录）；多账号用 `Start-Process -Environment` 显式传 `WECHAT_ACCOUNT`（靠 `$env:` 继承不可靠）。
