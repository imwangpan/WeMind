# 9. 配置项与环境变量

> 上一页：[8. 数据存储与多账号](08-数据存储与多账号.md) ｜ 下一页：[10. 部署与运维](10-部署与运维.md)
>
> **适用版本**：WeMind 1.2.0 ｜ **最后核对**：2026-10-28

WeMind 的可配置项几乎全部通过环境变量暴露，**改配置无需动代码**。本章按用途分类汇总。所有变量都有合理默认值，开箱即用。

## 9.1 数据目录与账号

| 变量 | 默认 | 说明 | 定义位置 |
|------|------|------|---------|
| `WEMIND_HOME` | `~/.wemind` | 数据根目录 | core: `store/accounts.ts` |
| `WECHAT_ACCOUNT` | `default` | 账号标识，决定子目录 `~/.wemind/<account>/` | core: `store/account.ts` |
| `WECHAT_DATA_DIR` | — | 直接指定完整数据目录路径，覆盖上面的规则 | core: `store/account.ts` |

多账号即「不同 `WECHAT_ACCOUNT` → 不同目录 → 完全隔离」。

## 9.2 iLink 协议与渠道

| 变量 | 默认 | 说明 | 定义位置 |
|------|------|------|---------|
| `WEMIND_ILINK_BASE` | `https://ilinkai.weixin.qq.com` | iLink API / 登录基础 URL（wemind 用） | daemon: `manage.ts` |
| `ILINK_CLIENT_VERSION` | `2.4.3` | 对外声明的 iLink 客户端版本（随官方升级可改，免动代码） | core: `api/client.ts` |
| `ILINK_APP_ID` | `bot` | iLink App Id | core: `config.ts` |
| `WECHAT_CDN_BASE_URL` | `https://novac2c.cdn.weixin.qq.com/c2c` | 媒体 CDN 基础 URL | core: `cdn/image.ts` |

> 注：MCP server 的 `tools/login.ts` 内默认基础 URL 为 `https://ilinkai.weixin.qq.com`（常量 `DEFAULT_BASE_URL`）。

## 9.3 登录者白名单（兜底）

| 变量 | 默认 | 说明 |
|------|------|------|
| `WECHAT_OWNER_ID` | 扫码登录该 bot 的微信号 user id | 登录者覆盖（白名单里始终放行的那一个；常规用配对授权写入 allowFrom，无需设此项） |

授权模型见 [8. 数据存储与多账号](08-数据存储与多账号.md#授权与安全)。

## 9.4 对话大脑（brain）

### 超时与进度

| 变量 | 默认 | 说明 |
|------|------|------|
| `WECHAT_BRAIN_IDLE_MS` | 120000 | 单回合空闲超时（多久无帧算卡死） |
| `WECHAT_BRAIN_CAP_MS` | 900000 | 单回合硬上限（15min；重任务实测约 6.5min） |
| `WECHAT_BRAIN_FIRST_FRAME_MS` | 内置默认值（默认 25000） | 首帧超时（开局即卡死的快速放弃阈值）；配置可覆盖（DSH 60000） |
| `WECHAT_BRAIN_HEARTBEAT_MS` | 内置默认值（默认 15000） | 静默期心跳间隔（无帧多久发一条「还在处理」）；配置可覆盖（DSH 60000） |
| `WEMIND_ACP_AUTO_ALLOW` | 未设置（拒绝） | agent 反向权限请求的应答策略：`1` 选 `allow_once` 放行，默认拒绝（`cancelled`）；未知反向请求一律回 `-32601` |

### Agent 选择与接入

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_BRAIN` | `auto` | 选 ACP agent（`kiro`/`opencode`/`gemini`/`deepseek`/`qoder`…；`auto`=探测已安装者）。**优先级最高，覆盖账号 `brain.json`** |
| `WEMIND_BRAIN_BIN` | 自动解析 | 覆盖二进制（绝对路径或 PATH 上的名字） |
| `WEMIND_BRAIN_ARGS` | 内置默认值 | 覆盖进入 ACP 模式的启动参数（空格分隔） |
| `WEMIND_BRAIN_HOME_ENV` | 内置默认值 | 覆盖「配置目录环境变量名」（指向 brain 沙箱） |
| `WEMIND_BRAIN_SHELL` | 内置默认值（默认 false） | 是否经 shell 启动（npx/.cmd 类在 Windows 需要） |
| `KIRO_CLI_BIN` | — | 旧的 kiro 专用二进制覆盖（仍兼容） |

> 上表是**环境变量一次性覆盖**（最高优先级）。**持久选择**用账号级 `<数据目录>/brain.json`：`wemind brain set <agent 名|auto> [--bin X] [--args "…"] [--model X|auto] [--restart]`（另见 `wemind brain` / `switch` / `unset` / `check`）。该命令现在是**读-改-写**（不再整体覆盖文件）；**只选 agent**（不带 `--bin`/`--args`/`--shell`/`--model`、也不带 `--restart`）且 daemon 在跑并**认控制桥**（`control-out/.bridge` 的 pid 对得上）时，它走**当场换大脑**（等价 `brain switch`：先启动新大脑、成功才写入磁盘，失败退回）；带 `--bin` / `--args` / `--shell` / `--model` 则退化为「只写入磁盘」（控制桥刻意不接受这些字段，是安全边界）——其中 `--bin`/`--args`/`--model` 的改动可由随后的 `wemind brain switch <同名 agent>` 当场应用，否则重启 daemon。`brain.json` 除 `agent` 外还有两个可选段：`presets`（按 agent 名保存 `--bin` / `--args` / `--shell` / `homeEnvVar` / `model` 这类覆盖，换 agent 时旧覆盖会迁移进来，避免「切走再切回丢 `--bin`」）与 `worker`（默认任务大脑，`{agent, bin?, args?, shell?, homeEnvVar?, model?}`；取值优先级见 9.6）。`model` 是默认模型（格式 `["provider 路由","模型名"]`，如 `'["deepseek-account","deepseek-flash"]'`）：会话建立后经 `session/set_config_option` 下发一次（显式覆盖以它为准），解析优先级「本段 > `presets[agent 名]` > 真实 profile 的默认 > 预设兜底」——「真实 profile 的默认」由 `profile-model.ts` 读（**优先用户自己写的 `- id: acp`，否则 `agent-default-model`**；`- id: acp` 由用户维护，缺了 `wemind brain` 会给片段）；写 `auto`/`default` = **跟随真实 profile 的默认**（DSH 读 `~/.dsh/profiles/acp/cordis.patch.yml`，典型 `["magpie","auto/deepseek-v4.1-flash"]`，需桌面端在运行；读不到就不下发——预设值 `["deepseek-account","deepseek-flash"]` 只在**没配** `model` 时兜底，写 `auto`/`default` 不会用它）。未配置时默认 `auto`（按 `kiro → opencode → gemini → deepseek → qoder` 探测第一个已安装者）。daemon **启动即校验**大脑，不可用会 `FATAL` 退出（退出码 78）。

### 运行时切换与会话

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_SWITCH_DRAIN_MS` | 30000 | 热切换时等在跑回合结束的上限（超时 = 诚实失败，不砍回合） |
| `WEMIND_SWITCH_TIMEOUT_MS` | 120000 | 启动新大脑（`initialize` + 会话）硬上限 |
| `WEMIND_CONTROL_TIMEOUT_MS` | 30000 | CLI 等 daemon 回话的上限；`brain switch` 会自动放大到 `启动新大脑 + 等在途回合结束 + 15s` |
| `WEMIND_HANDOFF_TTL_MS` | 86400000 | 交接摘要（`handoff.json`）的有效期，默认 24h；切到别的大脑后下一条用户消息作为前缀带上一次，答成才消费 |

> 运行时切换入口：微信 `切换大脑 [名]` / `/ai brain` / `/brain`，CLI `wemind brain switch <agent 名|auto>`（加 `--worker` 只设**默认任务大脑**：**本次运行内一直生效**、不写 `brain.json`，重启回到配置值）。`WEMIND_BRAIN` 仍是优先级最高的一次性覆盖：命令式切换在进程内生效并写入磁盘，但重启后 env 还在就会回到 env 指的大脑（答复里有警告，别写进 profile）。

### 记忆/规则继承

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_BRAIN_INHERIT` | `1`（开） | 是否继承真实配置目录的记忆/规则/技能 |
| `WEMIND_BRAIN_REAL_HOME` | 该 agent 的 `realHome`（kiro 为 `~/.kiro`） | 覆盖被继承的真实配置目录 |
| `WEMIND_BRAIN_INHERIT_DIRS` | agent inheritDirs | 覆盖继承的子目录清单（逗号/空格分隔） |
| `WECHAT_BRAIN_HOME` | `<数据目录>/brain-home` | brain 沙箱目录 |
| `WEMIND_MCP_CATALOG` | `<realHome>/settings/mcp.json` | 可选 MCP 的来源 mcp.json 路径 |

> 兼容别名：`WECHAT_BRAIN_INHERIT`、`WECHAT_REAL_KIRO_HOME`、`WECHAT_MCP_CATALOG` 与上面对应项等效（代码里同时识别）。

| 变量 | 默认 | 说明 |
|------|------|------|
| `WECHAT_CONSEC_SEND_LIMIT` | 10 | bot 在用户回复前可连续发送的消息数上限 |
| `WECHAT_MIN_SEND_GAP_MS` | 1500 | 两条发送之间的最小间隔（规避发送限流） |

## 9.6 远程任务（worker）

| 变量 | 默认 | 说明 |
|------|------|------|
| `WEMIND_WORKER_CWD` | 用户主目录 | worker 默认工作目录（本地 `task --cwd` 覆盖） |
| `WEMIND_WORKER_HOME` | `<数据目录>/worker-home` | worker 沙箱配置目录 |
| `WEMIND_WORKER_MCP_EXCLUDE` | `wechat` | worker 不继承的 MCP（`wechat` 始终强制排除，防它把消息发回自己） |
| `WEMIND_WORKER_IDLE_MS` | 180000 | worker 单轮空闲超时 |
| `WEMIND_WORKER_CAP_MS` | 1800000 | worker 单轮硬上限（30min） |
| `WEMIND_WORKER_FIRST_FRAME_MS` | 30000 | worker 首帧超时 |
| `WEMIND_WORKER_PROGRESS` | `0` | 是否推送 worker 全程文字进度（`1` 开启；「正在输入中」始终有） |
| `WEMIND_MAX_WORKERS` | 3 | 同时运行的**任务**数上限（超出派发被拒并提示） |
| `WEMIND_IDLE_MAX` | 2 | 池中保留的**空闲** worker 进程数上限 |
| `WEMIND_WORKER_REAP_MS` | 300000 | 空闲 worker 进程回收时间（5 分钟）；**它不是 `WEMIND_WORKER_IDLE_MS`**——后者是「单轮 prompt 空闲超时」，同名两义会踩 |
| `WEMIND_WORKER_BRAIN` | — | 默认任务大脑（agent 名）；优先级：env（`WEMIND_WORKER_BRAIN` → `WEMIND_BRAIN`）> `brain.json` 的 `worker.agent ?? agent` > `auto` |
| `WEMIND_TASK_SCAN_MS` | 1000 | daemon 扫描本地命令收件箱 `task-inbox/` 的间隔 |

worker 复用 brain 的 `WEMIND_BRAIN*` agent 解析（同一 `resolveAgent()`）；默认任务大脑按上表 `WEMIND_WORKER_BRAIN` 的优先级取值，也可用 `wemind brain switch <agent 名> --worker` 临时指定（**本次运行内一直生效**、不写 `brain.json`，重启回到配置值）。

## 9.7 常见配置场景

**放宽超长任务超时**（对话大脑）：

```
WECHAT_BRAIN_CAP_MS=1800000   # 30min
WECHAT_BRAIN_IDLE_MS=180000   # 3min
```

**切换到 Gemini CLI 当大脑**（推荐写入磁盘持久）：

```powershell
wemind brain set gemini --restart   # 写入账号 brain.json 并重启 daemon
```

```bash
# 或一次性覆盖（仅本次启动的 daemon）：WEMIND_BRAIN=gemini
```

**用绝对路径指定 agent 二进制**（绕开 PATH/shim）：

```powershell
wemind brain set kiro --bin "C:\Users\me\AppData\Local\Kiro-Cli\kiro-cli.exe"
# 或一次性覆盖：WEMIND_BRAIN_BIN=C:\Users\me\AppData\Local\Kiro-Cli\kiro-cli.exe
```

**多账号常驻**（每账号一套）：

```
WECHAT_ACCOUNT=work    # 账号 A
WECHAT_ACCOUNT=home    # 账号 B（不同进程）
```

**热切换大脑（不用重启 daemon）**：

```powershell
wemind brain switch gemini              # 走控制桥热切换；微信里也可发「切换大脑 gemini」
wemind brain switch gemini --worker     # 只把「默认任务大脑」设为 gemini（本次运行内一直生效，不写 brain.json）
```

等回合结束的上限 `WEMIND_SWITCH_DRAIN_MS`、新大脑启动的上限 `WEMIND_SWITCH_TIMEOUT_MS` 可调；带 `--bin` / `--args` / `--shell` / `--model` 的 `wemind brain set` 例外，**命令本身**只写入磁盘（控制桥不接受这些字段）——其中 `--bin`/`--args`/`--model` 可紧接着执行 `wemind brain switch <同名 agent>` 当场应用（`sameAgent()` 按 name/bin/args/model 判是不是同一个），`--shell` 不在判据里、只能重启 daemon（daemon 不认桥时都需重启，答复会写明）。

**调任务并发与进程池回收**：

```
WEMIND_MAX_WORKERS=6           # 同时最多 6 个任务
WEMIND_IDLE_MAX=4              # 池中最多保留 4 个空闲 worker
WEMIND_WORKER_REAP_MS=600000   # 空闲 worker 10 分钟回收（默认 5 分钟）
```

**给任务单独指定大脑**（对话仍走原大脑）：

```
WEMIND_WORKER_BRAIN=deepseek   # 或写进 brain.json 的 worker 段；CLI 亦可 wemind brain switch deepseek --worker
```

> 这些变量需对 **daemon 进程**生效。用 `scripts/run-daemon.ps1` / pm2 启动时在脚本或计划任务环境中设置；多账号用 `Start-Process -Environment` 显式传 `WECHAT_ACCOUNT`（靠 `$env:` 继承不可靠）。
