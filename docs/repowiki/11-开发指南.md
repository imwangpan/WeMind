# 11. 开发指南

> 上一页：[10. 部署与运维](10-部署与运维.md) ｜ 返回：[RepoWiki 首页](README.md)

本章面向想在 WeMind 上开发、调试、贡献的人，讲清构建顺序、测试、CI 与代码约定。

## 11.1 环境要求

- Node.js >= 20（已在 Node 24 验证，兼容 Bun）。
- npm（项目用 npm workspaces）。
- 若要跑 daemon 形态：需要一个 ACP agent CLI 在 PATH 上（如 `kiro-cli` / `opencode`；未配置时默认 `auto` 探测已安装者，用 `wemind brain set <预设>` 落盘指定）。

## 11.2 本地开发

```bash
git clone <repo>
cd WeMind
npm install           # 安装所有 workspace 依赖

npm run build         # 按 core → daemon/mcp-server 顺序构建
npm start             # 运行 MCP server（node packages/wechat-mcp/dist/index.js）
npm run daemon        # 运行守护进程（需先扫码登录）
npm test              # 运行单元测试（vitest）
npm run typecheck     # 仅类型检查

# 热重载开发 MCP server（可选）
npm run dev -w @wemind/wechat-mcp
```

## 11.3 构建顺序与产物

构建有**严格的依赖顺序**：core 必须先构建（daemon 直接引用其 `dist`，mcp-server 内联其源码）。根 `package.json` 的 `build` 脚本保证了这一点：

```jsonc
"build": "npm run build -w @wemind/wechat-ilink-core && npm run build -w wemind -w @wemind/wechat-mcp"
```

| 包                  | 构建工具 | 产物                                  | 说明                  |
| ------------------- | -------- | ------------------------------------- | --------------------- |
| `wechat-ilink-core` | `tsc`    | `dist/`（含 `.d.ts`）                 | 被另两个包消费        |
| `wemind`（原 `wechat-daemon`） | `tsdown` | `dist/cli.js`（单文件，内联 core） | 可发布的完整 CLI    |
| `wechat-mcp`        | `tsdown` | `dist/index.js`（单文件）             | 内联 core，是发布产物 |

入口路径：

- MCP server：`packages/wechat-mcp/dist/index.js`（bin: `wemind-mcp`）；
- daemon：`packages/wechat-daemon/dist/cli.js daemon`；
- 管理 CLI（与 daemon 同一入口）：`wemind`（产物 `packages/wechat-daemon/dist/cli.js`）。

## 11.4 TypeScript 配置

共享配置 `tsconfig.base.json`：target ES2022、module/moduleResolution NodeNext、`strict: true`、`declaration: true`、`esModuleInterop`、`resolveJsonModule`。各包的 `tsconfig.json` 继承它。

> **TypeScript 7.0（原生编译器）注意**：原生编译器不再像旧版那样自动把 `node_modules/@types` 全部纳入编译，因此各包 `tsconfig.json` 显式声明了 `typeRoots`（指向根 `../../node_modules/@types`）与 `types`（core 为 `["node"]`，daemon/mcp 含 `"qrcode"`）。漏掉会报 `TS2591 Cannot find name 'process'/'Buffer'` 一类错误。

全项目是 ESM（`"type": "module"`），import 路径带 `.js` 后缀（NodeNext 要求）。

## 11.5 测试

测试用 [vitest](https://vitest.dev/)，根目录 `npm test` 跑全部。现有测试：

| 测试                                              | 覆盖                                                                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `wechat-ilink-core/src/api/session-guard.test.ts` | 会话冷却：默认未暂停、暂停约 1h 后自动过期、`clearSessionPause` 立即解除（用假定时器）                                        |
| `wechat-daemon/src/task-manager.test.ts`          | 任务状态机：派发 → waiting → 注入续跑 → stop、二次派发被拒、中断推送「继续」、running 暂存 pendingInject、cwd 透传、状态 sink |

`task-manager.test.ts` 用 `vi.hoisted` + `vi.mock` 把 `worker-acp` 整个 mock 掉，纯测状态机逻辑（不真起 ACP 进程）—— 这得益于 task-manager 通过依赖注入（`setTaskPush`/`setTaskTyping`/`setTaskStateSink`）不直接依赖发送层/文件，保持纯逻辑可测。

写新测试时：放在同目录 `*.test.ts`，遵循「纯逻辑 + 依赖注入 mock 外部副作用」的模式。

## 11.6 持续集成（CI）

`.github/workflows/ci.yml`：在 push（`main`/`feat/**`/`fix/**`）与 PR 时，于 ubuntu + Node 22 跑：

```
npm ci → npm run lint → npm run format:check → npm run typecheck → npm run build → npm test
```

提交前本地跑一遍 `npm run lint && npm run format:check && npm run typecheck && npm run build && npm test` 可避免 CI 失败。

## 11.7 代码约定与风格

从源码可观察到的约定：

- **注释为「为什么」服务**：源码注释解释设计取舍、踩过的坑、关键约束（大量 `[实测]` 标注真机验证结论），而非复述代码。
- **防御性 I/O**：所有 JSON 落盘用原子写（临时文件 + rename）；读取坏文件不静默清空，而是备份 + 记日志。
- **错误分类正交**：业务错误码（`error-codes.ts`）与传输层错误（`transport-errors.ts`）分离。
- **依赖单向**：消费方只依赖 core，彼此不耦合；core 不依赖任何消费方。
- **配置优先 env**：可调项几乎都通过环境变量暴露，默认值合理，改配置不动代码。
- **Lint / 格式化**：`oxlint`（`correctness` 类规则，CI 上 error）+ `oxfmt`（`printWidth: 120`）统一把关；本地 `npm run lint` / `npm run format`，CI 跑 `lint` 与 `format:check`。
- **借鉴来源标注**：借鉴自 openclaw-weixin / wxclawbot-cli 等的实现都在注释与 CHANGELOG 注明（均 MIT）。

## 11.9 调试技巧

- **看日志**：daemon 所有日志写 `~/.wemind/<key>/daemon.log`，前缀区分子系统（守护进程统一命名空间 `[wemind/wechat-daemon]`）：`[wemind/wechat-daemon]`（主循环/发送）、`…/acp`（对话大脑）、`…/worker`（任务 worker）、`…/task`（任务状态机）、`…/watchdog`、`…/wrapper`（常驻看门狗）；内核侧 `[wemind/wechat-ilink-core]` 及其 `/ilink`（上下线通知）、`/store`、`/accounts`、`/allow-from`（持久化）子前缀。`tools/messages.ts` 里给客户端渲染用的 `[Image]`/`[Voice]`/`[File]`/`[Video]` 是**内容标签**（消息正文的一部分），不是日志前缀，故意保留。
- **验证 agent 解析**：`node --input-type=module -e "import {resolveAgent} from './packages/wechat-daemon/dist/brain-agents.js'; console.log(resolveAgent())"`。
- **关键日志线索**：`[wemind/wechat-daemon/acp] spawn ... → initialized → session/new|load → session/prompt → prompt ok` 表示一轮成功；`prompt FAIL ... -> rebuild` 表示大脑超时自愈。
