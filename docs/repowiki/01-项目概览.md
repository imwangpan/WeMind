## 1.1 一句话定位

WeMind 让任何 AI Agent 都能通过「个人微信」收发消息。它把腾讯官方的 iLink / 微信 ClawBot 渠道封装成两种可消费形态：一个 MCP Server 包（`@wemind/wechat-mcp`，**已发布到 npm，当前 1.1.2**），和一个常驻 daemon 包（`@wemind/cli`，命令 **`wemind`**，**已发布到 npm，当前 1.7.0**，见 [`docs/发布与变更记录/如何发布新版本.md`](../发布与变更记录/如何发布新版本.md)）。

口号：_Your AI mind, reachable on WeChat._ —— 你的 AI 大脑，在微信上随时可达。

## 1.2 Fork 由来

本项目 Fork 自 [Howardzhangdqs/mcp-wechat-server](https://github.com/Howardzhangdqs/mcp-wechat-server)（MIT）。相比上游，WeMind 做了大量演进，核心改动如下：

- **支持 Node.js 运行**：两个发布包由 `tsdown` 打成 `dist/` 单文件（core 内联），用 `node` 运行；协议内核是 JIT 源码包（入口指向 `src/index.ts`，`tsc --noEmit` 只做类型检查），并补齐 `engines.node >= 20.19.0`。
- **补齐 iLink 协议请求头**：`iLink-App-Id` / `iLink-App-ClientVersion`（连接的必要条件，缺失会被服务端拒绝）。
- **修复登录流程**：`get_bot_qrcode` 改为 POST + `local_token_list`，客户端版本对齐官方 `2.4.3`，解决扫码「无反应/秒过期」。
- **会话超时处理**：命中 errcode `-14` 后进入 1 小时冷却，补 `notifyStart` / `notifyStop` 上下线通知。
- **重构为 monorepo 三包**：把上游平铺的 `src/` 拆成协议内核、MCP server、daemon 三个 package。
- **新增常驻 daemon**：长轮询 + 常驻 ACP 大脑全自动收发，并演进出远程任务（worker）、多账号、收发图片、长回复转文件等大量能力。
- 修复回复引用（`ref_msg`）死代码、server 版本号硬编码、Windows 凭证权限处理与安全提示，补单元测试与 CI。

> iLink 协议细节、`session-guard` 与上下线通知的实现，借鉴自微信官方插件 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)（MIT）。
>
> 关于借鉴来源的说明已在源码注释与 CHANGELOG 中标注，相关内容均为 MIT 许可。

## 1.3 核心功能

### MCP Server 提供的能力

- **6 个 MCP 工具**：登录、检查扫码、登出、消息轮询、文本发送、打字状态。
- **扫码登录**：生成终端文本二维码、PNG 图片、URL 链接三种形式。
- **长轮询监听**：阻塞等待新消息，最长可等 7 天。
- **打字状态**：Agent 处理时显示「对方正在输入……」。
- **状态持久化**：重启不丢登录凭证与消息游标。

### daemon 额外提供的能力

- **全自动收发**：自己长轮询收消息 → 调常驻 AI 大脑生成回复 → 自动回发，无需任何 IDE。
- **常驻多轮记忆**：默认用常驻 ACP agent（`auto` 探测 opencode/cline/qoder/gemini/deepseek/kiro）进程，原生多轮上下文，回复从流式帧拼接（无 ANSI、无工具旁白；committed-only agent 只发整段）。
- **远程任务（worker）**：把漫长任务交给受控 ACP 工作机 —— 1.2.0 起是**多任务并行 + 进程池**（每条任务一条连接、派发时可指定 agent、编号寻址），在「需决策」或「中断」时推到微信，回一句即续跑（远程 human-in-the-loop）；任务表写入磁盘，daemon 重启后未完成的标「已中断」，回「继续」可续跑。
- **收发富媒体**：收图（AES 解密看图，需 agent 的 `images` 预设字段为真）、发图（回复里的 Markdown 图片引用）、长回复自动转 `.md` 文件发送、收语音（取微信侧转写文本）。内核的 `sendFile()` 还能按扩展名发视频（`kind: "video"`），但 **daemon 目前没有调用它**——微信侧不提供「发视频」入口。
- **多账号**：每个微信号一份独立目录，各跑一个 daemon，互不冲突。
- **可换大脑 + 运行时换大脑**：通过 ACP 接入其它 agent CLI（多数原生 ACP 可零代码）；微信里发 `切换大脑 <名>` 或 CLI `wemind brain switch <agent 名>` 即可**不重启 daemon** 换大脑，失败自动退回原来那个；跨大脑用 `交接` 生成摘要，切走后第一条消息自动带上。
- **会话管理**：`新会话 [名字]` / `会话列表` / `恢复会话 <序号|名字|id前缀>` / `重命名会话` / `删除会话`（微信与 CLI 同源）。
- **长回复转 `.md` 文件**：超阈值正文作为单个文件发送，规避连续发送上限。

## 1.4 技术栈

| 维度        | 选型                                                             |
| ----------- | ---------------------------------------------------------------- |
| 语言        | TypeScript 7.0（原生 Go，`strict`，ES2022，NodeNext）            |
| 运行时      | Node.js >= 20.19（从源码构建需 >= 22.18）                               |
| 仓库管理    | npm workspaces（monorepo）                                       |
| MCP 实现    | `@modelcontextprotocol/server` v2（stdio transport）             |
| 参数校验    | `zod`                                                            |
| 二维码      | `qrcode`（终端 ANSI + PNG）                                      |
| 打包        | `tsdown`（两个发布包，各自把 core 内联为单产物）；`tsc --noEmit`（全仓类型检查），core 无构建产物 |
| 测试        | `vitest`                                                         |
| CI          | GitHub Actions（lint + format + typecheck + build + test）       |
| AI 大脑协议 | ACP（Agent Client Protocol，JSON-RPC over stdio）                |
| 加密        | Node `crypto`（AES-128-ECB，收发图）                             |

## 1.6 三个 package 的职责与关系

| 包                          | 路径                         | 职责                                                                                                     | 发布                            |
| --------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `@wemind/wechat-ilink-core` | `packages/wechat-ilink-core` | iLink 协议内核：HTTP 客户端、类型、错误码、会话守卫、账号/状态持久化、收发图加解密。**不依赖任何消费方** | 私有（JIT 源码包；发布时 tsdown 内联进 `@wemind/cli` 与 `@wemind/wechat-mcp`） |
| `@wemind/wechat-mcp`        | `packages/wechat-mcp`        | MCP server：把内核能力暴露为 MCP 工具                                                                    | **已发布**（bin: `wemind-mcp`） |
| `@wemind/cli` | `packages/wechat-daemon`    | 独立常驻 daemon：长轮询 + 常驻 ACP 大脑自动收发 + 远程任务                                              | 已发布（命令 `wemind`）                |

> 📌 上表「发布」列指的是**该子包**是否发布到 npm，不代表整个 WeMind 项目：对外发布的是 `@wemind/wechat-mcp`（MCP 形态）与 `@wemind/cli`（完整应用 CLI，命令 `wemind`）两个入口。发版流程见 [`docs/发布与变更记录/如何发布新版本.md`](../发布与变更记录/如何发布新版本.md)。

依赖方向（单向，无循环）：

```
wechat-ilink-core  ◄──  wechat-mcp      （tsdown 内联打包，发布时无需单独发 core）
        ▲
        └──────────────  wechat-daemon  （发布为 `@wemind/cli`；构建时把 core 内联进产物）
```

关键设计：消费方（mcp / daemon）只依赖 core，彼此之间**互不耦合**。`@wemind/wechat-mcp` 与 `@wemind/cli` 发布时都用 tsdown 把 core 内联进单一产物，两个包各自自包含。

## 1.7 关于 iLink 渠道的限制（重要）

- 后端是腾讯官方 iLink / 微信 ClawBot 接口，面向**个人微信账号**，区别于企业微信。按官方用途使用，不存在逆向 bot 那类封号风险。
- **不能主动发起对话**：只能在收到用户消息后、于该会话上下文内回复（发送依赖收消息得到的 `context_token`）。
- **服务稳定性**：腾讯新开放的插件功能，官方保留随时停服的权利，勿用于关键业务。
- 需要较新的微信客户端并启用 ClawBot 插件。
