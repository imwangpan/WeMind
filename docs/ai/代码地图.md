# 代码地图（单文件职责）

> 从 [`AGENTS.md`](../../AGENTS.md) §2 拆出（2026-11-06），因为入口文件太大。路径相对仓库根。

> **先按任务找**：[`docs/ai/README.md`](README.md) §6 的「源码地图（按任务）」；这里回答的是「某个文件到底管什么」。

| 文件 | 职责 |
| --- | --- |
| `packages/wechat-daemon/src/index.ts` | 消息路由、回合编排、进度节流、brain/worker 分流、快车道（`fastWorkerLoop`）；轮询/收件箱扫描委派给 runner，纯路由判定在 `daemon-routing.ts`，微信/控制桥指令分派在 `daemon-control.ts` |
| `packages/wechat-daemon/src/daemon-routing.ts` | 纯路由判定（可单测）：快车道/「继续」归属、控制与任务指令解析、大脑错误分类与用户提示、文本/工具标题提取 |
| `packages/wechat-daemon/src/daemon-control.ts` | 微信控制指令与控制桥请求的分派：MCP/会话/切脑/任务大脑/交接/`AI` 总览/帮助；两入口共用同一批实现 |
| `packages/wechat-daemon/src/access.ts` | 发件人兜底鉴权：登录者始终放行，其余看登录者白名单 |
| `packages/wechat-daemon/src/control-inbox-runner.ts` | 控制桥收件箱扫描（`ControlInboxRunner`）：单条串行、过期不执行、失败一定写应答 |
| `packages/wechat-daemon/src/task-inbox-runner.ts` | 任务收件箱扫描（`scanTaskInbox`）：按时间序、先删后做、坏文件丢弃、出错回 ack |
| `packages/wechat-daemon/src/send-pipeline.ts` | 外发管线（`SendPipeline`）：串行链、最小间隔、按用户连发预算、旧 token 挂起/补发、任务推送让位；可注入假发送函数做单测 |
| `packages/wechat-daemon/src/acp-brain.ts` | 常驻 ACP 客户端（对话大脑）；含 `resumeSession`（严格恢复）、`beginSwitch/drainTurn/warmup`；协议细节走 `acp-connection.ts` |
| `packages/wechat-daemon/src/acp-quiet.ts` | `waitForFrameQuiet`：恢复会话后等异步回放帧安静（200ms 静默窗口、最多 3s；brain 与 worker 共用） |
| `packages/wechat-daemon/src/acp-reverse.ts` | 反向请求应答器（brain / worker / `brain check` 共用）：权限默认拒绝、`WEMIND_ACP_AUTO_ALLOW=1` 只选 `allow_once`/`allow_always`、未知 method 回 `-32601` |
| `packages/wechat-daemon/src/acp-connection.ts` | brain/worker 共用的 ACP 连接层：帧处理（响应/反向请求/`session/update` 进度与文本拼接）、请求与回合超时（首帧/空闲/硬上限）、模型与模式设置、`load` 后回放静默 |
| `packages/wechat-daemon/src/agent-slot.ts` | brain/worker 的 **agent 槽位**（懒解析 + 记忆化；`setAgent` 供热切换用） |
| `packages/wechat-daemon/src/brain-switch.ts` | 热切换：预检 → 等在途回合结束 → 启动新大脑 → 成功才写入磁盘；失败退回 |
| `packages/wechat-daemon/src/worker-acp.ts` | 任务 worker 的 ACP 客户端（`class WorkerConn`，一条任务一条连接） |
| `packages/wechat-daemon/src/worker-pool.ts` | worker 进程池（复用/回收/上限；`workers.pid.json` 记录，单条为对象、多条为数组） |
| `packages/wechat-daemon/src/task-manager.ts` | 任务表（编号、编号寻址、停止；默认任务大脑 + 进程内覆盖；`shouldResumeTask()` 决定无编号消息是否只按「继续」类短句进任务） |
| `packages/wechat-daemon/src/task-store.ts` | 任务表写入磁盘 `tasks.json`（损坏降级、中断标记、编号跨重启连续） |
| `packages/wechat-daemon/src/session-manager.ts` | 会话五条指令的实现层（`create`/`resume` 依赖注入） |
| `packages/wechat-daemon/src/session-registry.ts` | 会话登记表（派生元数据：名字/标题/轮次）——**不是**「当前是哪个」的权威 |
| `packages/wechat-daemon/src/handoff.ts` | 交接（摘要写入磁盘 + 作为前缀带上 + 答成才消费） |
| `packages/wechat-daemon/src/control-bridge.ts` | CLI↔daemon 文件桥（请求/应答/`.bridge` 凭据；**只收 agent 名与纯数据**） |
| `packages/wechat-daemon/src/task-inbox.ts` | 任务收件箱两个通道（`task-inbox/` 命令 + `task-out/` 答复，两侧共用；派发的答复等起进程有结果才发） |
| `packages/wechat-daemon/src/chat-commands.ts` | 命令表（解析 + 帮助**同表**驱动） |
| `packages/wechat-daemon/src/shared/process/pid-record.ts` | `brain.pid` / `workers.pid.json` 身份记录（JSON，含起进程时真实用的 bin/args） |
| `packages/wechat-daemon/src/brain-state.ts` | `brain-runtime.json`：daemon 实际生效的大脑（启动/热切换写入；`list` 只在 daemon 活着时采信） |
| `packages/wechat-daemon/src/brain-agents.ts` | `ACP_AGENT_PRESETS`（含 `model` / `modelArg` / `realProfile` / `envDefaults` / `sessionMode` / `requiresBins` / `settingsBase` / `settingsStrip` / `settingsDefaults` / `replayOnLoad` / `kiroEngine` / `isolateSessions` 字段）、`resolveAgent()`、`resolveAgentFor(cfg, role)`、`agentEnv()`、`agentProblem()`；派生配置落盘 `prepareAgent()`（DSH `--patch` 会话 root）、`ensureKiroV3Permissions()`（kiro v3 沙箱 `permissions.yaml`） |
| `packages/wechat-daemon/src/profile-model.ts` | 真实 profile 用户层四件事：`readProfileDefaultModel`（读默认模型——**优先用户自己写的 `- id: acp`**，否则 `agent-default-model`）；`acpOverrideHint`（缺 `- id: acp` 时在 `wemind brain` 里给出可粘贴的片段——**只提示，不替 agent 改配置**，AGENTS.md §4.14）；`acpModelHint`（`- id: acp` 的 model 已不在该 provider 模型目录时提示替换）；`stripWechatMcpEntries`（复制进沙箱前剔除用户自己挂的微信 MCP 条目，防回环，AGENTS.md §4.1） |
| `packages/wechat-daemon/src/mcp-sandbox.ts` | brain 沙箱、MCP 激活集；`syncKiroSettings` 复制设置后按引擎补 v3 的 `permissions.yaml` |
| `packages/wechat-daemon/src/worker-sandbox.ts` | worker 沙箱（继承全量 MCP，排除 wechat）；同样补 kiro v3 `permissions.yaml` |
| `packages/wechat-daemon/src/sandbox-inherit.ts` | 记忆/技能继承（brain 与 worker 共用）：junction/拷贝 + `.wemind-inherited.json` 清单，换 agent 时清掉上一个 agent 留下的 `skills`/`AGENTS.md` |
| `packages/wechat-daemon/src/shared/process/spawn-agent.ts` | 统一 spawn（Windows `.cmd` 经 shell + 逐参数引号） |
| `packages/wechat-daemon/src/brain-check.ts` | `wemind brain check` 的真 ACP 握手 |
| `packages/wechat-daemon/src/manage.ts` | `wemind` 入口与命令分派（生命周期、账号等仍在；brain/登录/任务/会话命令已拆到 `cli-brain.ts` / `cli-login.ts` / `cli-task.ts` / `cli-session.ts`） |
| `packages/wechat-daemon/src/cli-context.ts` | CLI 共用上下文：账号选择、daemon/控制桥存活判断、`viaBridge` |
| `packages/wechat-daemon/src/cli-task.ts` | `task` / `task-reply` / `task-stop` / `task-list` / `task-status` 的文件桥实现与答复文案 |
| `packages/wechat-daemon/src/cli-session.ts` | `session`（含 `current` 子命令）的 CLI 侧实现：列表读登记表、`current` 读当前会话表（`brain-sessions.json`），写优先走控制桥（daemon 不在时 `rename`/`delete` 可安全直改） |
| `packages/wechat-daemon/src/cli-brain.ts` | `brain show/set/unset/check/switch/handoff` 的 CLI 侧实现；`--restart` 的重启动作由入口注入（`startDaemon`），模块不反向依赖 `manage.ts` |
| `packages/wechat-daemon/src/cli-login.ts` | 扫码登录（独立暂存目录、二维码刷新、登记、可选自启）与登录后的 `session.unpause`；`--start` 的启动动作由入口注入 |
| `packages/wechat-mcp/src/tools/*` | 6 个 MCP 工具 |
