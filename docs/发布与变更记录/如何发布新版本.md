# 如何发布新版本

> 维护者操作手册：本文只讲「怎么发一个新版本」。命名与打包设计、Trusted Publisher 绑定、首次发布实录见 [发布-wemind-npm.md](发布-wemind-npm.md)；发布状态速查见该文档 §0。
>
> 最后核对：2026-11-04

WeMind 对外发布**两个独立的 npm 包**，各有自己的版本号、构建产物、workflow 与触发路径。内核 `@wemind/wechat-ilink-core` 是私有包，构建时由 `tsdown` 内联进两个产物，**永不单独发布**。

## 0. 两个包的发布内容对照

| 项 | `@wemind/cli`（命令 `wemind`） | `@wemind/wechat-mcp`（bin `wemind-mcp`） |
| --- | --- | --- |
| 源码目录 | `packages/wechat-daemon` | `packages/wechat-mcp` |
| 发布工作流 | [`.github/workflows/wemind-publish.yml`](../../.github/workflows/wemind-publish.yml) | [`.github/workflows/wechat-mcp-publish.yml`](../../.github/workflows/wechat-mcp-publish.yml) |
| 版本号唯一来源 | `packages/wechat-daemon/package.json` | `packages/wechat-mcp/package.json` |
| 本文核对时版本 | `1.4.0` | `1.0.5` |
| `bin` / `main` | `wemind` → `dist/cli.js` | `wemind-mcp` → `dist/index.js`（`main` 同） |
| `files` | `["dist"]`（npm 自动附 `README.md` / `LICENSE` / `package.json`） | `["dist"]`（同左） |
| 打进包的产物（`npm pack --dry-run` 实测） | **5 个**：`dist/cli.js`、`dist/cli.js.map`、`README.md`、`package.json`、`LICENSE` | **4 个**：`dist/index.js`、`README.md`、`package.json`、`LICENSE` |
| sourcemap | 有（`tsdown` 开 `sourcemap: true`）；`prepack` 守卫会检查 `.map` 随包 | 无 |
| 运行时依赖 | `qrcode`（懒加载，仅 `wemind login` 用到） | `@modelcontextprotocol/server`、`qrcode`、`zod` |
| 装包冒烟 | 真装 tarball → `wemind version` / `wemind help` | 真装 tarball → 临时 `WECHAT_DATA_DIR` → MCP `initialize` → 断言 `serverInfo.name = wemind` |
| 发布命令 | `npm publish --workspace @wemind/cli --provenance --access public` | `npm publish --workspace @wemind/wechat-mcp --provenance`（`publishConfig.access: public` 已写进 package.json，故不再传 `--access`） |
| `check-version` 是否校验 | ✅ 校验（包名 / bin / lock / 无硬编码版本号） | ❌ 不校验：`scripts/check-version.mjs` 只认 `@wemind/cli`；MCP workflow 自己有一段内联的版本与 lock 一致性校验 |

两个 workflow 都由 **`push main` + 路径过滤** 触发，也都支持 `workflow_dispatch` 手动运行；`concurrency` 组各自独立（`publish-wemind-cli` / `publish-wechat-mcp`），互不取消。

## 1. 判断要不要发版

**关键规则：两个 workflow 都先检查「这个版本号是否已发布」，没发过才 `npm publish`，已发过只跑检查并输出 `::notice::` 跳过。** 所以判断标准不是「有没有改代码」，而是「**有没有升版本号**」；版本没升就只会跑一次全量校验，不会发布（也不会报错）。

| 你改了什么 | 触发的 workflow | 要发版吗 |
| --- | --- | --- |
| `packages/wechat-daemon/**` | `wemind-publish.yml` | ✅ 升 `@wemind/cli` 版本 |
| `packages/wechat-mcp/**` | `wechat-mcp-publish.yml` | ✅ 升 `@wemind/wechat-mcp` 版本 |
| `packages/wechat-ilink-core/**` | **两个都会**（core 内联进两个产物） | ✅ 两个版本都要升 |
| `scripts/prepack-guard.mjs` / `scripts/check-version.mjs` | 仅 `wemind-publish.yml` | ✅ 升 cli 版本 |
| 根 `package.json` / `package-lock.json` / `tsconfig.base.json` | 两个都会 | 视改动而定 |
| 只改 `*.md` 文档 | 若在 `packages/*/` 下仍会让对应 workflow 跑一次（路径匹配），但版本没升 → 跳过发布 | ❌ |

> 同一个版本号**不能重复发布**。想真正发版，唯一动作是升版本号后推 `main`。

## 2. 选版本号

两个包都用 semver，规则一致，例子各自独立：

| 参数 | 什么时候用 | `@wemind/cli` 示例 | `@wemind/wechat-mcp` 示例 |
| --- | --- | --- | --- |
| `patch` | Bug 修复、兼容性改动（**最常用**） | `1.4.0 → 1.4.1` | `1.0.5 → 1.0.6` |
| `minor` | 新增向后兼容的能力（新内置 agent、新子命令 / 新 MCP 工具） | `1.4.0 → 1.5.0` | `1.0.5 → 1.1.0` |
| `major` | 不兼容改动（删命令 / 工具、改数据目录布局、改 CLI 参数 / 工具参数） | `1.4.0 → 2.0.0` | `1.0.5 → 2.0.0` |

## 3. 发布 `@wemind/cli`

### 3.1 升版本号

```bash
npm run release:patch       # 或 release:minor / release:major
```

等价于：

```bash
npm version patch -w @wemind/cli --no-git-tag-version && npm run check:version
```

- 前半句同时改 **`packages/wechat-daemon/package.json` 与根 `package-lock.json`** 两处；`--no-git-tag-version` 让它**不**自动创建 commit / tag（本项目要求「版本号 + 源码改动」在同一个 commit 里）。
- 后半句 `check-version` 校验：包名仍是 `@wemind/cli`、`bin` 仍叫 `wemind`、lock 已同步、`src/version.ts` 没有被改回硬编码版本号；任一项不对就 `exit 1`。

指定具体版本或手动改：

```bash
npm version 1.4.2 -w @wemind/cli --no-git-tag-version
# 或：改 packages/wechat-daemon/package.json 的 version，再
npm install --package-lock-only --ignore-scripts
```

> **版本号只有一处来源**：`packages/wechat-daemon/package.json`；`src/version.ts` 在运行时读它，不要手写常量，也不要手动编辑 `package-lock.json`。

### 3.2 本地校验

```bash
npm run verify              # lint + format:check + typecheck + build + check:version + 两包 pack + test + 文档链接检查
npm pack --dry-run --workspace @wemind/cli    # 应看到 5 个文件
```

- ⚠️ **`npm publish` 不会自动 build**。`dist/` 在 `.gitignore` 里，本地 `npm pack` / 发版前必须先 `npm run build`，否则打出来的是旧产物。
- `prepack` 守卫（`scripts/prepack-guard.mjs .`）兜底拒绝：`files` 目录为空、`bin` 缺失、或声明了 sourcemap 却没把 `.map` 带进包。它只能挡「产物缺失」，挡不住「产物是旧的」。

### 3.3 提交并推送

```bash
git add packages/wechat-daemon/package.json package-lock.json
git add packages/wechat-daemon/src packages/wechat-ilink-core/src   # 有源码改动时
git commit -m "chore: release @wemind/cli 1.4.0"    # 换成当前要发的版本
git push origin main
```

### 3.4 CI 会做什么（`wemind-publish.yml`）

```
check-version → npm ci → 补装 Linux rolldown 原生绑定
→ lint → format:check → typecheck → build → test
→ npm pack --dry-run（prepack 守卫确认包内容）
→ 把 tarball 真装到临时目录跑 wemind version / help（装包冒烟）
→ 检查 npm 上是否已存在该版本
→ 不存在则 npm publish --provenance --access public（Trusted Publishing / OIDC）；已存在则跳过并输出 notice
```

runner 是 `ubuntu-latest` + Node 24；`id-token: write` 用于 provenance。**看到 `Publish to npm` 显示 skipped 是正常的**：说明这个版本已发过（或只改了文档没升版本）。

### 3.5 发布后验收

```bash
npm view @wemind/cli version                     # 新版本号
npm i -g @wemind/cli@latest && wemind version    # → wemind <新版本> (@wemind/cli, node …, <platform>-<arch>)
wemind list                                      # 应正确识别在跑的账号与进程
npx -y @wemind/cli list                          # 验证「npx 写全包名」这条路
```

已装用户升级：`npm i -g @wemind/cli@latest`，然后 `wemind stop <账号> && wemind start <账号>` ——**正在运行的 daemon 不会自动加载新代码**。

### 3.6 发布成功后：同步文档

这一步不在 npm 包里、也没有自动检查会拦，但漏了会立刻变成事实错误（文档与发布版本对不上）：

- `AGENTS.md` 头部与 `README.md` 页脚的「最后核对」日期；`docs/ai/README.md` 的「最后核对」；
- `发布-wemind-npm.md` 头部「当前线上版本」与 §0 速查（版本、包内容文件数、体积、日期）；`docs/repowiki/01-项目概览.md` 的已发布版本状态；
- `CHANGELOG.md` 的段头日期用**实际发布日**（写这一节时可能还没发）。

更完整的背景见 [发布-wemind-npm.md](发布-wemind-npm.md) §6.7。

## 4. 发布 `@wemind/wechat-mcp`

### 4.1 升版本号（两种方式二选一）

**方式 A：用 npm 自动提升（推荐）**

```bash
npm version patch --workspace @wemind/wechat-mcp --no-git-tag-version
```

它同时更新 `packages/wechat-mcp/package.json` 的 `version` 与根 `package-lock.json` 里该 workspace 的版本记录；只动本包，不改根项目 / daemon / core 的版本。

**方式 B：手动改两处**

1. 编辑 `packages/wechat-mcp/package.json` 的 `"version"`；
2. 在仓库根目录刷新 lock：

```bash
npm install --package-lock-only --ignore-scripts
```

> 不要手动编辑 `package-lock.json`；这条只重算元数据，不重装 `node_modules`、不跑安装脚本。

⚠️ **`npm run check:version` 不校验本包**（它只认 `@wemind/cli`）。MCP workflow 自己有一段内联校验：读 `packages/wechat-mcp/package.json` 与 `package-lock.json` 的 `packages["packages/wechat-mcp"].version` 对比，不一致就 `exit 1`。

### 4.2 本地校验

```bash
npm run verify
npm pack --dry-run --workspace @wemind/wechat-mcp    # 应看到 4 个文件
npm pkg get version --workspace @wemind/wechat-mcp   # 确认版本号已改
```

同样：**`npm publish` 不会自动 build**，本地打包前先 `npm run build`；`prepack` 守卫同样生效。

### 4.3 提交并推送

```bash
git add packages/wechat-mcp/package.json package-lock.json
git add packages/wechat-mcp/src packages/wechat-ilink-core/src   # 有源码改动时
git commit -m "chore: release @wemind/wechat-mcp 1.0.6"
git push origin main
```

### 4.4 CI 会做什么（`wechat-mcp-publish.yml`）

```
校验 MCP 包版本与 lock 一致（内联 node 脚本）→ npm ci → 补装 Linux rolldown 原生绑定
→ lint → format:check → typecheck → build → test
→ npm pack --dry-run
→ 装包冒烟：临时 WECHAT_DATA_DIR，向 wemind-mcp 发 MCP initialize，
  断言握手回包含 serverInfo 且 name = wemind
→ 检查 npm 上是否已存在该版本
→ 不存在则 npm publish --provenance；已存在则跳过并输出 notice
```

冒烟用临时数据目录，不会碰 runner 上的真实账号；stdin 关闭后 server 正常退出。这也是与 CLI 冒烟最大的差别（CLI 验 `wemind version`，MCP 验协议握手）。

### 4.5 发布后验收

```bash
npm view @wemind/wechat-mcp version
wemind-mcp                     # 全局安装后的命令；应打印 Connected / Not logged in 后挂在 stdio（Ctrl+C 退出）
npx -y @wemind/wechat-mcp      # 不安装直接运行的等价写法
```

## 5. 两个包一起发（改了 `core` 时）

`packages/wechat-ilink-core/**` 同时命中两个 workflow 的 `paths`，而 core 被内联进两个产物——所以改了 core 就必须**两个包都升版本、同一个 commit 推 `main`**，否则只有一个包会带上新内核。两个 workflow 各自独立跑（`concurrency` 组不同），互不取消；都绿了才算发完。

顺序建议：先分别升两个版本号 → 一次 `npm run verify` → 一个 commit 同时带上两处 `package.json` + `package-lock.json` + 源码 → push。

## 6. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| CI 绿了但 npm 上没新版本 | 版本号没升，被 `Check whether this version is already published` 跳过 | 升版本号后再推 |
| `check-version` 报「lock 版本不一致」 | 手改了 cli 的 `package.json` 没刷新 lock | `npm install --package-lock-only --ignore-scripts`，或改用 `npm run release:*` |
| `check-version` 报「硬编码 CLI_VERSION 字面量」 | 有人把 `src/version.ts` 改回了常量写法 | 还原为 `readOwnVersion(...)`（版本号必须只来自 package.json） |
| MCP workflow 第一步报「版本不一致」 | 只改了 `packages/wechat-mcp/package.json`，没刷新 lock | 补跑 §4.1 方式 B 第 2 步 |
| `npm pack` 出来是空壳 / 旧产物 | 没先 `npm run build`（`dist/` 不入库） | 先 build 再 pack |
| `prepack` 守卫拒绝 | 产物为空 / `bin` 缺失 / 声明了 sourcemap 却没带 `.map`（仅 cli） | 按守卫提示补 build 或检查 `files` |
| `npm publish` 报 403 / EOTP | 本地直发需要交互式 2FA | **不要本地发**，走 CI（Trusted Publisher 已配好） |
| MCP 装包冒烟失败 | `initialize` 回包缺 `serverInfo.name = wemind` | 检查 `packages/wechat-mcp/src/index.ts` 的 `serverInfo`；冒烟用临时 `WECHAT_DATA_DIR` 复现 |
| 发版后文档还写着旧版本 | 漏了 §3.6 的同步清单 | 按 §3.6 逐项改并补一次 `check-docs` |
