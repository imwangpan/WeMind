# 待办：任务编号语义与任务记录体积

> **状态**：暂缓（2026-10-31 记录，当前先保持现状）｜ **适用范围**：WeMind 1.2.0
> **触发原因**：真机测试时任务编号已到 `#19`，用户反馈「数字一直累计」不自然；同时 `tasks.json` 会永久保留未结束的 `interrupted` / `waiting` 记录。
> **当前结论**：**本轮不改**，先记录方案与风险，后续单独评估。

---

## 1. 现状（不要误改）

- `tasks.json` 的 `nextId[userId]` 按用户**单调递增、只增不减、永不复用、跨重启连续**（`task-store.ts`）。
- 编号是「生命周期唯一 ID」，不是「当前任务列表序号」：
  - 好处：聊天记录里的 `#7 继续` 永远指同一个任务；
  - 代价：数字无限增长，测试/废弃任务也占号。
- 任务记录保留 `interrupted` / `waiting`，只有「结束任务 <编号>」或被保留策略淘汰才删除；`lastOutput` 存完整输出。
- `lastOutput` **只用于展示/推送，不参与续跑**；续跑靠 `worker-sessions.json` 的 sessionId。

当前真机样本（2026-10-31）：`tasks.json` 9.1 KB，11 条记录，`nextId=20`；单条 `lastOutput` 最长 1677 字符。

---

## 2. 编号方案（后续可选，未实现）

### A. 活跃槽位号（复用最小空闲编号）— 最符合“任务序号”直觉

- 新任务取当前未占用的最小正整数；任务被结束/淘汰后编号释放。
- `running` / `waiting` / `interrupted` 都占号（interrupted 还要 `#n 继续`）。
- 优点：数字小、与 `任务列表` 对得上、测试任务不永久占号。
- 风险：
  1. 旧聊天里的 `#2 继续` 在 #2 复用后可能指向新任务；
  2. `worker-sessions.json` 的 key 现在是 `task-<id>@<user>`，复用 id 会接上旧会话 → **必须**改成带代际的唯一 key（如 `task-<id>-<startedAt>@<user>`）或清理旧条目；
  3. 现有 #7–#19 的迁移：不建议强行重排（会改 session 键）；新任务先填 #1–#6，接受过渡期。
- 可加护栏：记录还在就不复用；或编号释放后 24h 内不复用（需要额外状态）。

### B. 短随机任务码（唯一、不增长）

- 新任务用 4 位短码（如 `#k7m2`），不复用；旧数字任务保留兼容。
- 优点：永不歧义、不增长、无旧会话复用问题。
- 缺点：输入/记忆成本高；命令解析与文档改动大；新旧混号。

### C. 展示层小序号（内部 ID 不变）

- 内部仍是唯一 ID，`任务列表` 显示 1..N 的当前序号，命令按序号映射到内部 ID。
- 优点：兼容旧引用；缺点：序号会随列表变化，实现复杂，容易误解。

**后续选择建议**：优先评估 A（配代际 session key），若更看重“绝不歧义”则选 B；C 暂不建议。

## 3. 记录体积（相关，未实现）

- **截断 `lastOutput`**：持久化时保留末尾 N 字符（默认建议 2000），只影响 `tasks.json` / `task-state.json` 展示；内存中的完整结果先推送微信。
- **终态记录上限**：每用户最多保留 N 条 `interrupted`（建议 50），`running` / `waiting` 永不淘汰；`nextId` 不变。
- **waiting 老化（可选）**：超过 M 条或 TTL 后转 `interrupted`（不删除），避免陈旧任务吞掉无编号消息；会改变路由行为，需通知。
- **归档（可选）**：淘汰记录移到 `tasks-archive.json`；收益有限（微信聊天记录已是归档），暂不建议。

---

## 4. 若实施，必须一起做

1. `task-store.ts`：分配/回收编号（或短码）、保留策略、`lastOutput` 截断，全部纯函数 + 单测；
2. `task-manager.ts`：`persist()` / `initTasks()` 触发清理；`worker-sessions.json` 的 key 代际化/清理；
3. 迁移：旧 `nextId` / 旧任务编号的兼容；不重排旧任务；
4. 文档：AGENTS、README、`docs/使用指南-远程任务（worker）.md`、repowiki 07、run-e2e；
5. 验收：跨重启编号行为、旧 `#n` 引用、`#n 继续`、并发任务、`tasks.json` 体积上限。

---

## 5. 相关观察（不在本待办范围）

- **Cline 的 `新会话` 不隔离文件系统**：Cline 会用 `run_commands` / `search_codebase` 搜索工作目录，而它的旧 session transcript 在 `brain-home/cline/data/sessions/`（cwd 内），所以新会话仍可能翻出旧暗号。这是工具型 agent 的预期行为，不是 WeMind session 映射 bug；后续可评估 `.clineignore` 或把数据目录移出 cwd（都只是降低概率，`run_commands` 仍可读任意路径）。
