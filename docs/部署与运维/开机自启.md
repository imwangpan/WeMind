## 0. 先认名词

| 名词 | 在这里指什么 |
|------|--------------|
| **触发器** | 系统在登录或开机时执行一条命令的配置。它只负责「拉起来一次」。 |
| **启动器** | `wemind start`（按账号启动后返回）或 `wemind daemon`（前台常驻）。 |
| **常驻进程 / 守护进程** | 在后台长期运行、崩溃后自动重拉的进程。 |
| **supervisor** | 系统自带的进程管理器，例如 Linux 的 systemd、macOS 的 launchd、第三方 PM2。它会替你重拉。 |
| **内置 watchdog** | `wemind start` 拉起的后台守护进程（`_watchdog`），跨平台，负责重拉和单实例检查。 |
| **计划任务** | Windows「任务计划程序」里的登录触发任务。 |
| **Run 键** | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的启动项，登录时执行。 |
| **systemd / launchd** | Linux / macOS 的系统服务管理器。 |
| **PM2** | Node.js 生态的第三方进程管理器。 |
| **bot token** | 微信机器人的登录凭证；同一个 token 同时只能有一个进程收消息。 |
| **Mutex** | Windows 的互斥锁，用来保证同一时间只有一个实例在运行。 |
| **cgroup** | Linux 的进程分组；systemd 停服务时默认会结束整组进程。 |
| **PATH** | 系统查找可执行文件的目录列表。 |
| **pid / `wrapper.pid`** | 进程号 / 记录后台守护进程号的锁文件，用来防止同一账号启动两次。 |

## 1. 一句话

`wemind autostart install` 一条命令：检测到 PM2 就用 PM2 托管；否则按平台生成系统触发器。触发器**只拉起一次**，之后由内置 watchdog（Windows 原生方案）或系统 supervisor（Linux / macOS）负责崩溃重拉。

## 2. 三个角色，别混在一起

「开机自启」常被当成一件事，实际有三层；混在一起就会写出错方案。

| 角色 | 负责什么 | 谁来做 | 缺了会怎样 |
|------|----------|--------|------------|
| ① 触发器 | 登录 / 开机时执行一次 | Windows 计划任务或 Run 键、systemd、launchd、PM2 自启项 | 什么都不启动，通常没有任何报错 |
| ② 启动器 | 选择账号、准备环境、拉起常驻进程 | `wemind start ...` / `wemind daemon` | 起错账号或起不来 |
| ③ 常驻 | 崩溃后重拉；防止同一账号重复启动 | 内置 watchdog / systemd / launchd / PM2 | 崩一次就停，或两个进程抢同一个 bot token |

关键区别：

- **Windows**：系统触发器本身不是 supervisor，所以触发器后面必须有内置 watchdog。触发器执行 `wemind start --all`（或 `start <key…>`）；`start` 拉起常驻进程后立刻返回。
- **Linux / macOS**：systemd / launchd 本身就是 supervisor，所以它们的服务单元直接执行 `wemind daemon`（前台常驻）。如果执行 `wemind start`，它会拉起后台进程后立刻退出，supervisor 会判「服务已退出」并无限重拉；systemd 默认还会连带杀掉 `start` 摘出去的整组进程（cgroup）。
- **PM2**：同时提供常驻与自启；Windows 上还需要一个登录任务来启动 PM2。

> **硬约束**：触发器绝不执行 `wemind autostart install`——每次登录都重新安装会递归。

## 3. 命令怎么用

```bash
wemind autostart install                          # 所有已登记账号（默认）
wemind autostart install --key <key>              # 只装一个账号
wemind autostart install --label 工作号            # 按别名选一个（别名必须唯一）
wemind autostart status                           # none / native-only / pm2-only / mixed
wemind autostart uninstall                        # 清理 PM2 实例与系统触发器
```

- `install` 默认安装**所有已登记账号**；`--key` / `--label` 只装指定的一个。`--label` 命中多个账号时会报错并提示改用 `--key`；一个账号都没有时会提示先运行 `wemind login`。
- 拼错的参数、裸的账号名不会被静默当成「装全部账号」；`help` / `--help` / `-h` 只打印用法，不会真的安装。
- `--key` / `--label` 是子命令参数，必须在通用全局开关解析之前拦住，否则会被 `--label` 抽走。
- `status` 只检查触发器与 PM2 配置，不代表 daemon 正在运行；运行状态看 `wemind list`。
- `uninstall` 清理触发器。**Windows 原生模式下已经运行的 daemon 不会被它停止**，需要再执行 `wemind stop <key>`；PM2、Linux、macOS 模式会随实例 / 服务一起停止。

## 4. 安装时按什么顺序决策

1. 解析目标账号：默认全部；`--key` / `--label` 指定一个。
2. 检测是否同时存在系统触发器与 PM2 实例（`mixed`）。是则让用户选择保留哪一套，并按选择清理。
3. 检测 PM2：
   - 已安装且本次没有选择「保留系统触发器」：用 PM2 托管，实例名 `wemind-<key>`；Windows 再创建一个登录任务 `wemind-autostart-pm2`。
   - 未安装：使用系统原生触发器。
4. 系统原生触发器按平台生成：
   - Windows：计划任务，失败则降级 Run 键。
   - Linux：systemd 用户单元。
   - macOS：LaunchAgent。

### 默认装哪些账号（Windows 和 Linux / macOS 不一样）

**Windows 原生模式**的触发器执行 `wemind start --all`，它在**每次登录时**读取 `accounts.json`：

- 新登录一个账号 → 下次登录自动纳入，**不用重新安装**；
- 删除一个账号 → 注册表里没了 → 下次登录自然不再拉起；
- 用户不需要为 N 个账号手写 N 条配置。

明确只装某个账号时（`--key` / `--label`），Windows 触发器参数写的是 `start <key>`，而不是 `--all`；**即使机器上只有一个账号**也保持这个区别，否则以后新增的账号会被自动带上。

**Linux / macOS** 是按安装时的账号列表逐个生成服务单元，不是一条 `start --all` 命令：

- 新登录账号后要重新运行一次 `wemind autostart install`，新账号才会有自己的单元；
- 默认安装（全部账号）会先清理旧的 `wemind@*` / `dev.wemind.*` 单元，因此删除账号后重跑 `install` 会同步移除它的服务；
- 只装指定账号时不会动其它账号的单元。

`start --all` 逐个账号启动，某个账号失败不会阻断其余账号，最后汇总并返回退出码 1。`start <key1> <key2>…` 会先解析全部 key，任意一个无效则一个都不启动（这两种写法只在 Windows 触发器里用到；Linux / macOS 单元直接执行 `daemon`）。

## 5. 为什么用这些方案

| 选择 | 原因 |
|------|------|
| Windows 首选**计划任务** | 系统级、不需要管理员权限、可设「不限时长」、不依赖用户目录写权限。 |
| 计划任务失败时降级 **Run 键** | 有些受管机器禁止创建计划任务；Run 键同样不需要管理员。代价是它会出现在「任务管理器 → 启动」里，用户可能手动禁用。 |
| 不用启动文件夹 + `.lnk` | 快捷方式的「运行方式」只有常规 / 最大化 / 最小化，**没有隐藏**。 |
| 不用启动文件夹 + `.bat` / `.cmd` | 直接启动批处理会新建一个控制台窗口，登录时闪一下。 |
| 不用 VBS | VBScript 正在被 Windows 逐步弃用；本项目约定不使用 VBS。 |
| 不装成 Windows 服务 | 需要管理员；服务运行在 Session 0（Windows 的隔离会话，不能与用户桌面交互）；对一个「个人微信通道」来说过重。 |
| Linux / macOS 用系统原生 supervisor | 不重复实现重拉；保留 `systemctl status` / `launchctl` 和系统日志的原生体验。 |
| 检测 PM2，但不自动安装 | 不让自启功能平白多一个依赖；机器上已有 PM2 时优先用它，便于统一管理多账号。 |
| `run-daemon.ps1` 默认只做薄壳 | 源码路线与发布版共用同一套 watchdog 实现，避免修一个 bug 改两遍；旧循环留在 `-Mode shell`。 |

## 6. Windows 细节

- **任务名**：原生模式 `wemind-autostart`；PM2 模式 `wemind-autostart-pm2`。用不同名字区分用途，状态探测不必解析任务内容。注册表 Run 值同名。
- **触发方式**：`AtLogOn`，以**当前用户**运行，不需要管理员；不使用 `/RU SYSTEM`（那会落到 Session 0，拿不到用户环境）。
- **动作**：
  - 原生：`"<node 绝对路径>" "<cli.js 绝对路径>" start --all`；只装部分账号时是 `start <key…>`。
  - PM2：同一条命令再加 `--runner pm2`。
  - 路径来自 `process.execPath` 与 `process.argv[1]`，并先解析符号链接 / 目录联接；登录时 PATH 找不到 `wemind` / `node` 也能启动。fnm 的 `fnm_multishells` 是每个 shell 临时创建的联接目录，直接记录 `process.execPath` 会在重启后指向不存在的路径，所以安装时必须解析到真实安装位置。
- **设置**：`-ExecutionTimeLimit ([TimeSpan]::Zero)`（默认是 72 小时，不设 0 会在三天后被杀）、`-MultipleInstances IgnoreNew`、`-StartWhenAvailable`。`TaskSettings.Hidden` 只影响任务是否出现在任务计划程序列表里，**不等于**隐藏窗口。
- **注册方式**：固定位置的 Windows PowerShell 5.1（`%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`）+ `Register-ScheduledTask`，不依赖 PATH 或 PowerShell 7。
- **降级**：注册失败（受管机器拒建任务）时写入 `HKCU\...\Run`，值是同一条命令。
- **安装前先清理**：旧的同名任务 / Run 键、另一种用途的触发器都会先删掉，避免登录时启动两次。清理是尽力而为，失败不会阻止新触发器创建。
- **安装不会立即启动**：Windows 原生模式只注册触发器，当前会话不会马上起 daemon；要现在运行请执行 `wemind start --all`。PM2 模式会先停掉当前账号的旧链再启动实例（否则旧 daemon 占着 token，pm2 会以退出码 75 退出）；Linux / macOS 的安装也会立即启动服务。
- **不使用 VBS**。

## 7. Linux / macOS 细节

### 7.1 Linux：systemd 用户单元（用户级服务配置）

`~/.config/systemd/user/wemind@<key>.service`：

```ini
[Unit]
Description=WeMind daemon (<key>)
After=network.target

[Service]
Type=simple
Environment=WECHAT_ACCOUNT=<key>
Environment=WECHAT_DATA_DIR=
Environment=WEMIND_HOME=<自定义根目录，仅在设置时写入>
Environment=PATH=<安装时的 PATH>
ExecStart="<node>" "<cli.js>" daemon
Restart=always
RestartSec=5
RestartPreventExitStatus=75 78

[Install]
WantedBy=default.target
```

安装后执行 `systemctl --user daemon-reload`、`enable`、`restart`；任一步失败都会报错并停止，不会打印「已安装并启动」。`WECHAT_DATA_DIR=` 空值是刻意覆盖：自启按账号 key 寻址，空值让 core 回退到 `<根>/<key>`，避免从用户管理器继承旧目录。`WEMIND_HOME` 只在安装时设置过才写入，保证 daemon 找到同一个根目录。`PATH` 在安装时写死，是为了让 daemon 找得到 ACP agent（接收消息并生成回复的 AI 程序）的可执行文件（fnm / nvm / Volta 等 Node 版本管理器装的工具通常只在用户 PATH 里）。`RestartPreventExitStatus=75 78` 与内置 watchdog / pm2 一致：同账号已有实例（75）或大脑配置错误（78）时不再重拉。如果 `loginctl show-user` 看不到 `Linger=yes`，会提示执行一次 `loginctl enable-linger <用户>`，否则用户登出后服务会停止。

单元只继承这里列出的环境变量；API key 等不会从交互 shell 自动带过去，需要手动写进单元（例如 `Environment=DEEPSEEK_API_KEY=...` 或 `EnvironmentFile=`）。

### 7.2 macOS：LaunchAgent（登录服务配置）

`~/Library/LaunchAgents/dev.wemind.<key>.plist`：

- `ProgramArguments = [node, cli.js, "daemon"]`
- `EnvironmentVariables = { WECHAT_ACCOUNT, WECHAT_DATA_DIR（空值，覆盖用户会话里的旧值）, WEMIND_HOME（仅在设置时）, PATH }`
- `RunAtLoad = true`、`KeepAlive = { SuccessfulExit: false }`
- 日志：`<账号目录>/daemon.log`

覆盖前先 `launchctl unload`（忽略「未加载」），写完再 `launchctl load`。和 systemd 一样，API key 等环境变量不会从 shell 自动带过去，需要写进 `EnvironmentVariables`。

### 7.3 为什么单元里是 `daemon` 而不是 `start`

`wemind start` 拉起后台守护进程后立刻退出。systemd / launchd 看到主进程退出，会认为服务失败并重拉；systemd 默认的 `KillMode=control-group` 还会在结束时杀掉整组进程，包括 `start` 摘出去的后台守护进程。所以 POSIX 单元必须直接跑 `wemind daemon`，让 supervisor 自己能一直看到主进程。

## 8. PM2 路径

- **探测**：`detectPM2()` 执行 `pm2 --version`。Windows 上 pm2 是 `.cmd`，用整条命令字符串过 shell，避免同时传参数数组（Node 20+ 的弃用警告）。
- **不自动安装**：只在已经装好 pm2 时使用；没有 pm2 就走系统原生触发器。
- **实例名**：`wemind-<key>`（用 key 不用 label：label 可含中文 / 空格，key 稳定）。
- **Linux / macOS**：安装时提示用户执行一次 `pm2 startup` 和 `pm2 save`，并用标记文件 `<WEMIND_ROOT>/.pm2-persistence-configured` 记住「已经提示过」，以后不再重复。注意：即使当时没照做，也不会再提醒。
- **Windows**：`pm2 startup` 不原生支持 Windows。安装登录任务 `wemind-autostart-pm2`，动作是 `node cli.js start --all --runner pm2`；由它按声明重建实例并执行 `pm2 save`。任务动作不是 `pm2 resurrect`，但 `wemind start --runner pm2` 内部仍会调用 `pm2`，所以 **pm2 必须在登录环境的 PATH 中**（npm 全局安装通常已经满足）。
- **状态**：`autostart status` 会说明当前是不是 PM2 托管；Windows 上如果缺少登录任务，会提示「重启后 PM2 实例不会自动恢复」。

## 9. 双重配置（mixed）

`detectMixedConfig()` 返回四种状态：

| 状态 | 含义 |
|------|------|
| `none` | 都没有 |
| `native-only` | 只有系统触发器 |
| `pm2-only` | 只有 PM2：有 `wemind-*` 实例，或 Windows 上存在 PM2 登录任务 |
| `mixed` | 两者都有——同一账号会被拉起两次，抢同一个 bot token |

`install` 检测到 `mixed` 时会要求人工选择：

1. 只保留系统触发器（删除所有 PM2 实例）；
2. 只保留 PM2（删除所有系统触发器）；
3. 全部清空，再按默认优先级安装。

选 1 时本次安装会跳过「检测到 PM2 就用 PM2」的默认分支（`forceNative`），否则刚清掉的 PM2 会被立刻装回来，等于没听用户的选择。选 2 / 3 则继续按默认优先级安装；如果此时 PM2 已不可用，就会落到系统原生方案。

清理是**尽力而为**的：删除 PM2 实例后会执行 `pm2 save`（不同步的话，`pm2 resurrect` 会在重启后把旧实例拉回来），`pm2 save` 失败会给出警告。清理系统触发器失败也不会抛错，但 `install` 会继续；`status` 仍会显示实际状态。选择无效（不是 1 / 2 / 3）会直接报错退出。

**旧版启动文件夹项不在自动探测范围内**：如果之前按旧文档在 `shell:startup` 放过 `wemind*.vbs` / `.bat` / `.cmd` / `.lnk`，它会在登录时再执行一次 `wemind start`。`startDaemon()` 会先停掉已存在的 wrapper / daemon 再拉起新的（防止双跑），所以表现不是「两个 daemon」，而是**任务刚拉起的 daemon 被旧项接管一次**。`autostart install` 只清理自己创建的 Windows 任务 / Run 键，不会动这些用户文件；迁移到 `autostart install` 时请手动删除旧项，只保留一套。

## 11. 源码开发者

`scripts/run-daemon.ps1` 默认是 **cli 薄壳**：定位 node 与仓库里的 `dist/cli.js`，然后执行 `wemind start`，重拉交给内置 watchdog。这样源码开发者和发布版用户跑的是同一条代码路径。

- 需要旧的 PowerShell 监督循环时用 `-Mode shell`（命名 Mutex、`wrapper.pid`、每次重拉前轮转日志）。
- `-All` 传给 `wemind start --all`；`-Account <key>` 传给 `wemind start <key>`；两者不能同时使用。
- `-DryRun` 只打印将执行的命令，不启动进程。
- `scripts/run-all-daemons.ps1` 用于手动启动多个账号；不要和 `wemind autostart` 同时配置同一账号（会启动两套）。
- 同一账号只用一套常驻方案：内置 watchdog / `run-daemon.ps1 -Mode shell` / PM2 三选一。

## 13. 风险与已知限制

| 风险 | 现状 / 应对 |
|------|-------------|
| 受管 Windows 禁止建计划任务 | 自动降级 `HKCU\...\Run`；两者都不需要管理员。Run 键会出现在任务管理器启动项里。 |
| fnm / nvm / Volta 管理的 node 不在登录 PATH | 自启记录 node 与 cli.js 的绝对路径，并解析到真实安装位置（避开 fnm 的临时 `fnm_multishells` 联接），启动 daemon 没问题；但 daemon 拉起的 ACP agent 仍靠 PATH——需要把全局 bin 加进持久 PATH，或给 agent 配绝对 `--bin`。 |
| systemd 用户服务在登出后停止 | 安装时检测 `Linger`，提示 `loginctl enable-linger`。 |
| systemd 崩溃循环被限速 | 默认 10 秒内最多启动 5 次，超过后进入 `start-limit-hit`，停止重试；这与内置 watchdog 的无限重拉不同。 |
| macOS 对退出码 78 也会重拉 | `KeepAlive.SuccessfulExit=false` 会在任何非零退出后重拉，而内置 watchdog 对 78（大脑配置错误）会停止。launchd 会按自己的节流间隔反复尝试，这是已知差异。 |
| PM2 提示只出现一次 | 标记文件只避免重复提醒；如果第一次没执行 `pm2 startup` / `pm2 save`，以后不会再提示，需要自己补。 |
| 升级 CLI 后自启项路径失效 | 自启记录的是安装时的 node + cli.js 绝对路径；升级后若路径变化（例如换了 Node 版本），重新执行 `wemind autostart install`。npm 全局安装的 cli.js 路径通常不变。 |
| 旧版启动文件夹项（`wemind*.vbs` / `.bat` / `.cmd` / `.lnk`） | `autostart` 不自动探测 / 清理；它会在登录时再执行 `wemind start`，把任务拉起的 daemon 停掉后重建。迁移时手动删除，只留一套。 |
| 双重配置 | `status` 可见、`install` 人工确认、`uninstall` 全清。 |
| Linux / macOS 新增账号不自动生效 | 单元是按安装时的账号列表逐个生成的；新增账号后要重新运行 `wemind autostart install`（Windows 的 `start --all` 不需要）。 |
| 源码开发者与发布版混用 | 源码版 `autostart` 记录仓库的 `dist/cli.js`；发布版记录全局安装路径。两者对同一账号只用一套。 |
| Linux / macOS 未真机验证 | 生成器已实现并有代码审查，但只有 Windows 是当前真机目标；POSIX 结论标注为待实测。 |
