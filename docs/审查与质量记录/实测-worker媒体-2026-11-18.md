# 真机实测：worker 接收 / 发送非文本消息（2026-11-18）

> 记录一次完整的真机验证：范围是「把图片/文件/视频发给 worker 任务」与「worker 结果里发图片/文件/视频」两件事，以及过程中改动的任务列表、任务状态、派发回执。
>
> 最后核对：2026-11-18 ｜ 被测版本：`main` @ `758a3f7`（`@wemind/cli` 2.1.0 之后、2.2.0 之前） ｜ 设计依据：[远程任务（Worker）：接收、发送非文本消息设计与实现](../设计文档/远程任务（Worker）接收、发送非文本消息设计与实现.md)

## 1. 结论

- 19 条用例全部通过（含 3 条需要特殊环境的：真实 mp4、`images: false` 的 agent、`managed` 模式）。
- 测试过程中发现并修掉 **6 个真实缺陷**（见 §5），其中 3 个是「文案说错了、但功能正常」，2 个是只在特定时序下才出现的状态错投，1 个是示例被当成命令执行。
- 未覆盖：真实的公网 http 图片（本机代理把它解析成 `198.18.x`，被 SSRF 闸拦下）、`允许敏感文件` 之外的外发大文件、多账号并发。

## 5. 测试中发现并修掉的问题

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 发「好了」后回「⏳ 正在按 #N 号任务续跑」却记成 `failed:`，还跳过续期 | `deliverPending()` 拿 `injectTask` 的返回值非空当失败判据，而续跑会返回一句提示 | `injectTask` 加 `onOutcome(ok)`，按成功/失败分流（`26d07d1`） |
| 示例 `[视频](file:///…/demo.mp4)` 被当成真命令，报 `ENOENT` | 解析不认代码区，行内代码里的写法被当真 | 新增 `maskCodeRegions()`，解析前把围栏与行内代码抹成等长空白（`e22d094`） |
| 首条任务回执没有编号 | `ackFor()` 对「单任务且未指定 agent」用免编号文案，但它同时会 arm 收件人 | 统一带编号，删掉免编号分支（`4b0d659`） |
| 任务列表说「先用 `#N` 看它最近在做什么」 | 裸 `#N` 是设收件人，不查任何信息；近况本来就在末列 | 删掉该指引并加反向断言（`f0acd60`） |
| 收件人回执 `（再发文字、「好了」就一起提交）` | 顿号读成「两个都要发」 | 改 `（再发一句文字，或发「好了」，就一起提交）`（`32f68fd`） |
| `全部继续` 回执把「看进展」写成 `#N 正文` | 三条指令语义混了（列表/设收件人/补话） | 改文案并改用真实编号（`5fb3b21`） |

## 6. 确认过、但不是 bug 的边界

- **一张图 = 一条微信消息 → 大脑一个回合**：连发多张时，大脑会逐张回复「收到 1 张图片，下载识别中…」。收件人模式才把多张并成一批。
- **合成 mp4 上传 CDN 会 500**：只有 `ftyp`/`mdat`、没有 `moov` 的视频不合法。真实 mp4 正常，`no_need_thumb` 无需改动。
- **本机公网 http 图片被拦**：代理把域名解析成 `198.18.x`，`assertPublicUrl` 判为内网（`拒绝访问本机/内网地址: …`）。这是既有闸的行为，brain/worker 一致。
- **`images: false` 的 agent 收到图**：不报错，只推一句「这台 worker 不支持图片输入」，日志留痕。
- **重启会把没跑完的任务转「待继续」**：`waiting` 在重启后也没有进程，同样转。
