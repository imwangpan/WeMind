## 1. 这次审计实际查出了什么

把发现按**成因**归类，只有四类（按出现频次排）：

| # | 成因 | 典型发现 | 为什么难防 |
|---|---|---|---|
| C1 | **同一事实写了 N 遍** | global-vs-npx 表在 3 处；环境变量表在 4 处（速查 / README / 随包 README / repowiki 09） | 改一处不会报错，只有人肉比对才发现 |
| C2 | **探针看不到的语义** | pi 的 worker 沙箱是「全量复制 MCP」而非「激活集」；Gemini 的 `streamHistory` 不 await | 探针只证明「这条消息能跑通」，证明不了「它内部怎么处理」 |
| C3 | **「实测」强度被混为一谈** | 探针观测 / 读上游源码 / 转述他人文档，写出来都叫「实测」 | 读者无法判断该结论的可信度 |
| C4 | **凭印象断言** | 我把 `TaskSettings.Hidden` 写成「隐藏窗口」（实为「不在任务列表里显示」） | 越是「我熟悉的平台」，越不查 |

**C4 值得单独记一笔**：这次唯一一次被自己的核实推翻的断言，发生在我最有把握的地方。这不是能力问题，是**流程问题**——没有任何机制要求「写平台事实前必须查一次」。

## 2. 五条教训

### 2.1 规则对 AI 无效，检查才有效

`AGENTS.md` 已有 16 条不变量，§4.15 明确写了「代码 + 测试 + 文档同一次改完，漏一个都算不一致」。而我在**同一次会话**里就漏了、也错了一次。

原因不是没读，是 **§4.15 是一个开放式判断**——「按读者找全」要求 AI 自己枚举所有可能受影响的文档。AI 会做一次 best-effort 的 grep，然后合理地宣布完成。**开放判断 → 主观完成；闭集清单 → 可查证完成。**

> 结论：不要再往 `AGENTS.md` 里加规则，要加**会变红的命令**。

### 2.2 最危险的文档错误是「方向性」的

本次唯一的 P0 是：`WEMIND_ACP_AUTO_ALLOW=1` 被列在「想收紧权限」清单里——它实际是**放松**权限。读者照着做会削弱安全边界。

这类错误和「版本号写旧了」不是一个量级：前者会让用户做出错误的安全决策。

> 结论：**安全 / 权限 / 默认放行**相关的表述需要单独一轮反向审查（专门找「把放松写成收紧」），不能混在常规审校里。

### 2.3 「实测」必须分三档写

| 档 | 含义 | 能证明什么 | 这次的例子 |
|---|---|---|---|
| **探针观测** | `acp-probe.mjs` 跑过一次 | 这条消息能跑通、回了什么 | pi 首帧 0–3ms |
| **源码核实** | 读了 node_modules / GitHub 的实现 | 它内部**怎么**处理 | Gemini `streamHistory` 不 await |
| **文档转述** | 官方文档/issue 的表述 | 作者声称的行为 | systemd `KillMode=control-group` |

**这次所有 C2 类发现都来自「源码核实」，没有一条来自探针。** 而文档里三者都叫「实测」。

> 结论：接入文档的每条结论标注来源档位；「待实测」单列小节（见 [`add-acp-agent.md`](../ai/recipes/add-acp-agent.md) 的产出物清单）。

### 2.4 写平台事实前必须先查

以下三条我原本都会写错，全部由核实纠正：

- `TaskSettings.Hidden` 只表示「不在计划任务列表显示」，**不是**隐藏窗口；
- `TaskSettings.ExecutionTimeLimit` 默认 **PT72H**，不显式设 0 会在三天后被杀；
- `.lnk` 的 `IShellLink::SetShowCmd` 只接受 1/3/7，**没有** `SW_HIDE`。

> 结论：**跨平台行为、系统 API 默认值、弃用时间线**这三类，写之前必须查一手来源，并在文档里给出出处（这次已按此修正原《自启方案对比》§8；该文已并入《开机自启》）。

### 2.5 大 fan-out 受 provider 配额约束

13 个集群 × 2 次尝试 = 26 次启动，13 次因「积分耗尽」失败，1 次 schema 违规。

> 结论：集群数要按配额算，不要按维度数算；每个 agent 设 token 预算上限；失败后重试要限定次数并记录原因，否则后半程全是噪音。
