## 1. 这次审计实际查出了什么

把发现按**成因**归类，只有四类（按出现频次排）：

| # | 成因 | 典型发现 | 为什么难防 |
|---|---|---|---|
| C1 | **同一事实写了 N 遍** | global-vs-npx 表在 3 处；环境变量表在 4 处（速查 / README / 随包 README / repowiki 09） | 改一处不会报错，只有人肉比对才发现 |

## 2. 五条教训

### 2.1 规则对 AI 无效，检查才有效

`AGENTS.md` 已有 16 条不变量，§4.15 明确写了「代码 + 测试 + 文档同一次改完，漏一个都算不一致」。而我在**同一次会话**里就漏了、也错了一次。

原因不是没读，是 **§4.15 是一个开放式判断**——「按读者找全」要求 AI 自己枚举所有可能受影响的文档。AI 会做一次 best-effort 的 grep，然后合理地宣布完成。**开放判断 → 主观完成；闭集清单 → 可查证完成。**

> 结论：不要再往 `AGENTS.md` 里加规则，要加**会变红的命令**。

### 2.2 最危险的文档错误是「方向性」的

本次唯一的 P0 是：`WEMIND_ACP_AUTO_ALLOW=1` 被列在「想收紧权限」清单里——它实际是**放松**权限。读者照着做会削弱安全边界。

这类错误和「版本号写旧了」不是一个量级：前者会让用户做出错误的安全决策。

> 结论：**安全 / 权限 / 默认放行**相关的表述需要单独一轮反向审查（专门找「把放松写成收紧」），不能混在常规审校里。

### 2.3 「实测」必须分三档写

| 档 | 含义 | 能证明什么 | 这次的例子 |
|---|---|---|---|
| **探针观测** | `acp-probe.mjs` 跑过一次 | 这条消息能跑通、回了什么 | pi 首帧 0–3ms |
| **源码核实** | 读了 node_modules / GitHub 的实现 | 它内部**怎么**处理 | Gemini `streamHistory` 不 await |
| **文档转述** | 官方文档/issue 的表述 | 作者声称的行为 | systemd `KillMode=control-group` |

**这次所有 C2 类发现都来自「源码核实」，没有一条来自探针。** 而文档里三者都叫「实测」。

> 结论：接入文档的每条结论标注来源档位；「待实测」单列小节（见 §4）。

### 2.4 写平台事实前必须先查

以下三条我原本都会写错，全部由核实纠正：

- `TaskSettings.Hidden` 只表示「不在计划任务列表显示」，**不是**隐藏窗口；
- `TaskSettings.ExecutionTimeLimit` 默认 **PT72H**，不显式设 0 会在三天后被杀；
- `.lnk` 的 `IShellLink::SetShowCmd` 只接受 1/3/7，**没有** `SW_HIDE`。

> 结论：**跨平台行为、系统 API 默认值、弃用时间线**这三类，写之前必须查一手来源，并在文档里给出出处（这次已按此修正 `自启方案对比.md` §8）。

### 2.5 大 fan-out 受 provider 配额约束

13 个集群 × 2 次尝试 = 26 次启动，13 次因「积分耗尽」失败，1 次 schema 违规。

> 结论：集群数要按配额算，不要按维度数算；每个 agent 设 token 预算上限；失败后重试要限定次数并记录原因，否则后半程全是噪音。

## 3. 约束设计：三层，按性价比排序

**总原则：把「要改哪些文档」从记忆问题变成查表问题。**

### 3.1 第一层 · 让 CI 不绿（最有效）

三个脚本，全部只读、全部进 `npm run verify`。

#### ① `scripts/doc-impact.mjs` —— 本次最该做的一件事

**问题**：AI 改了代码，忘了文档。现有 CI 完全不知道「这次 diff 碰了代码却没碰文档」。

**做法**：声明一张「代码路径 → 必须同步的文档」映射表，检查本次 diff 两侧是否配对。

```bash
npm run doc-impact                 # 读 diff，打印本次改动必须同步的文档清单（人/AI 照着改）
npm run doc-impact:check         # 断言这些文档确实在同一个 diff 里，否则 exit 1
```

**输入**：`git diff --name-only <base>...HEAD`（默认 base = `main` 的 merge-base；`--staged` 用于 pre-commit）。

**规则表**（`scripts/doc-impact.rules.mjs`，与脚本同目录，导出数组）：

| id | 触发条件（改动了…） | 必须同步的文档（闭集） |
|---|---|---|
| `env-var` | `packages/*/src/**` 的 `+` 行新增 `process.env.X` | 速查 §6/§7、`README.md` 环境变量表、`packages/wechat-daemon/README.md` 表、`repowiki/09`、`AGENTS.md` §6 |
| `preset` | `brain-agents.ts` 的 `+` 行新增 `name: "<x>"` | `docs/接入方案/接入-<x>.md`（结构见 §3.2③）、`接入其它-ACP-Agent.md` §5 表、`AGENTS.md` §6、`docs/README.md`、`llms.txt`、`docs/ai/README.md` 事实表 |
| `cli-command` | `manage.ts` / `chat-commands.ts` 的 `+` 行新增 `case "…"` 或命令表项 | `README.md`、`新手教程`、`速查`、`packages/wechat-daemon/README.md`、`AGENTS.md` §3 |
| `data-file` | `store/*.ts` / `*-store.ts` 改文件名或结构 | `repowiki/08`、`速查`、`AGENTS.md` §4 |
| `behavior` | `daemon-routing.ts` / `task-manager.ts` / `send-pipeline.ts` 等改逻辑 | 对应 `repowiki/05`·`07`、`AGENTS.md` §6、`ai/recipes/run-e2e.md` 验收表 |
| `script` | `scripts/*.ps1` / `*.mjs` 新增或改语义 | `repowiki/10`、`daemon-常驻原理`、`AGENTS.md` §3 |
| `new-doc` | 新增 `docs/**/*.md` | `docs/README.md`、`llms.txt`（已在 `check-docs.ps1` 之外，因为断链查不出「没被索引」） |
| `release` | `packages/*/package.json` 的 `version` 变化 | `CHANGELOG.md`、`如何发布新版本.md` |

**逃生口（必须有，否则机制会被绕穿）**：提交信息或 PR body 含 `Docs-Impact: none` + 一句理由（纯重构 / 行为不变 / 只改注释）。`--check` 见到该 trailer 直接放行并在输出里打印理由。**没有逃生口的检查，一定被 `--no-verify` 绕过，整套机制归零。**

**实现要点**：

- 判定用 **diff 行的启发式**（`+` 行里出现 `process.env.[A-Z_]+`），不是 AST。它不追求完备——**误报的代价是「多改一篇文档」或「加一行豁免」，漏报才是真问题**；而规则表本身就是「该改哪些」的完整说明。
- 输出必须是**人/AI 能直接照着做的清单**（路径 + 为什么 + 该改哪节），不是一串 id。
- 只在有 diff 时跑；`main` 上的 `push` 无 base 就跳过。

#### ② `scripts/gen-docs-tables.mjs` —— 让表格与代码强一致

**问题**：C1（多副本不同步）无法靠 diff 检查发现——「文档里少了一行」不会出现在任何 diff 里。

**做法**：对**可从代码枚举**的三张表，用标记块生成 + 断言。

```markdown
<!-- BEGIN:auto env-vars -->
| 变量 | 默认 | 作用 | 出处 |
...
<!-- END:auto env-vars -->
```

```bash
npm run docs:tables            # 重新生成标记块内的表格
npm run docs:tables:check   # 断言文档内容与代码枚举结果一致，否则 exit 1
```

**可生成的三张表**（仅此三张）：

| 表 | 枚举来源 | 落地位置 |
|---|---|---|
| 环境变量 | `grep -rhoE 'process\.env\.[A-Z][A-Z0-9_]*' packages/*/src`（实测 **59 个**，已排除测试） | `repowiki/09`、`速查` |
| 内置预设 | `ACP_AGENT_PRESETS` 的 `name` 字段（实测 **9 个**） | `接入其它-ACP-Agent.md` §5 |
| CLI 命令 | `manage.ts` 的 `case` 分支 + `chat-commands.ts` 命令表 | `README.md` |

**明确不做**：散文、说明、坑位描述**不生成**。AI 生成的说明文字会稀释文档质量——这次审计的核心结论之一就是「散文要靠人写，表格才靠机器」。

#### ③ `scripts/check-agent-docs.mjs` —— 新 agent 的结构断言

**问题**：接新 agent 时，文档「写了」但结构残缺（缺「已知限制」、缺「待实测」），读者拿不到该拿的信息。

**做法**：对 `ACP_AGENT_PRESETS` 里每个预设，断言：

1. `docs/接入方案/接入-<name>.md` **存在**；
2. 文件头部有 `最后核对` / `实测环境` / `状态` 三个字段；
3. 标题里含以下**语义**（用关键词正则，不按序号，因为现有文档编号不统一）：

   | 必需项 | 关键词 |
   |---|---|
   | 怎么装 | `安装` \| `准备` |
   | 预设做了什么 | `预设` \| `沙箱` |
   | 探针结论 | `探针` \| `实测` |
   | 限制 | `限制` \| `坑` \| `待实测` |
   | 验证 | `验证` \| `复现` |

4. 该预设名出现在 `接入其它-ACP-Agent.md` §5 表、`AGENTS.md` §6、`docs/README.md`、`llms.txt`。

**必须用「祖父条款」**：脚本内置 `KNOWN_GAPS` 白名单，列出当前不满足的既有文档（如 `接入-Codex.md` 无独立「验证」节）。**CI 只对新加入的文档失败**——否则一次性全红，没人会去修，脚本立刻被注释掉。白名单每修一篇删一条，本身就是进度表。

#### ④ 挂载点

| 位置 | 跑什么 | 理由 |
|---|---|---|
| `npm run verify` | 三个新脚本全部 | 与 CI 同口径；任何跑 verify 的 AI 自动覆盖 |
| CI `build-test` job | 同上（verify 已含） | 无额外改动 |
| `.githooks/pre-commit` | `check-docs` + `doc-impact --check --staged` + `check-agent-docs` | 三项合计 < 1s |

**钩子必须保持在 1–2 秒**。现在只跑 `format:check`（158ms）。加进慢检查 = 被 `--no-verify` 跳过 = 机制作废。

### 3.2 第二层 · 强制枚举（表单化）

AI 不会「记得」，但会「照着空格逐项填」。

**① PR 模板固定一节**

`.github/PULL_REQUEST_TEMPLATE.md`（**当前不存在**，需新建）：

```markdown
## 文档影响
- [ ] 已同步下列文档（逐项列出路径 + 改了哪节）
- [ ] 无（理由：____）
```

配合 `gh pr view --json body` 可断言该节存在且未留空。

**② `add-acp-agent.md` 改成填空模板**

现状是散文 + 决策门表格（§0 已有决策门，做得不错），但**没有强制产出物清单**。改为在每个槽位强制写：

- 「能力来源：探针 / 源码 / 文档」三选一；
- 「未验证项：____」（空也要写「无」）。

**③ 每篇接入文档必须有 `## 待实测` 小节**

这次 Gemini 的「微信侧 `加载 <MCP>` 未复测」埋在正文第 105 行句末——等于没有。独立小节才能被检索、被 `check-agent-docs` 断言。

**④ `acp-probe.mjs --emit-doc`（可选）**

探针跑完直接输出可粘贴的「探针实测结论」表格。**让人抄写而不是回忆**——本次 8 条 P2 全是回忆型错误（`thought_level` 档位、`sessionCapabilities` 字段、`promptCapabilities` 三元组）。

### 3.3 第三层 · 降低表面积（去重 + 拆分）

**① 同一个事实只在一处写全，别处只给结论 + 链接**

本次错误最多的类型就是多副本不同步。§3.1① 的 `global-vs-npx` 表已按此合并到 `接入其它-ACP-Agent.md` §5 一处，其余位置改为一行结论 + 链接。**这是根治，其余两层是兜底。**

**② `AGENTS.md` 拆开**

现状 **98829 字节（≈97KB）**，其中 §6 + §7 约占三分之一。长指令会被跳读——人和模型都一样。

| 拆分 | 去向 | 大小 |
|---|---|---|
| §0–§5（认识项目、命令、硬约束、改哪里） | 留在 `AGENTS.md` | ~10KB，**真的会被读完** |
| §6 已知坑 | `docs/ai/已知坑.md` | 按关键词检索，不要求通读 |
| §7 验证标准 | `docs/ai/验收清单.md` | 按改动类型查表 |

拆分后 `AGENTS.md` 首屏只剩「必读」，§6/§7 变成**按需检索的参考表**——这本来就是它们该有的形态。

**③ §4 的每条不变量标注「由哪个测试守」**

现在 16 条不变量全是「愿望」。改成：

```markdown
11. **控制桥只接受「agent 名 + 纯数据」**……（守卫测试：`control-bridge.test.ts`「请求 schema 无 bin/args/shell」、`「id 拒绝 ../」`）
```

守不住的标「**未覆盖**」并进待办。这样「不变量」从宣言变成可审计项——例如 §4.11 应当有一条测试断言 schema 里没有 `bin`/`args`/`shell`、id 正则拒绝 `../`。

### 3.4 可选 · 陈旧雷达（非阻塞）

`src 路径 → 文档` 映射，报「源码改过但文档「最后核对」没动」。只输出警告、不 exit 1——它能提示「可能该看一眼」，但改代码不改行为是常态，做成硬失败只会逼人改日期敷衍。

## 4. 接新 agent 的强制清单（直接回答「怎样才不遗漏」）

把 `add-acp-agent.md` 的产出物收成**闭集**。接一个新 agent 必须同时产出：

| # | 产出物 | 位置 | 由谁检查 |
|---|---|---|---|
| 1 | 预设 | `brain-agents.ts` 的 `ACP_AGENT_PRESETS` | 单测 |
| 2 | 预设单测 | `brain-agents.test.ts` | `npm test` |
| 3 | 沙箱单测（若涉及沙箱） | `sandbox-<name>.test.ts` | `npm test` |
| 4 | **接入文档** | `docs/接入方案/接入-<Name>.md`，含 §3.1③ 的 5 类小节 + `## 待实测` | `check-agent-docs.mjs` |
| 5 | 通用表加一行 | `docs/接入方案/接入其它-ACP-Agent.md` §5 | `check-agent-docs.mjs` |
| 6 | 已知坑加一条 | `AGENTS.md` §6 | `check-agent-docs.mjs` |
| 7 | 全库索引 | `docs/README.md`「各 agent 实测」行 + `llms.txt` | `check-agent-docs.mjs` |
| 8 | AI 事实表 | `docs/ai/README.md` 事实状态表 | 人工（表格结构不适合断言） |
| 9 | 安装提示（适配器类） | `brain-agents.ts` 的 `ADAPTER_INSTALL_HINT` | 单测 |
| 10 | 探针记录 | 文档 §「探针实测结论」，每条标来源档位（§2.3） | 人工审校 |

**第 4–7 项由 `check-agent-docs.mjs` 断言**——这是把「接新 agent 要写文档」从规范变成 CI 红绿的唯一办法。

## 5. 分批落地建议

| 批次 | 内容 | 工作量 | 收益 |
|---|---|---|---|
| **第一批** | `doc-impact.mjs` + 规则表 + 挂进 verify 与钩子 | ~0.5 天 | **最高**：直接回答「改了代码忘了文档」 |
| **第二批** | `check-agent-docs.mjs` + `KNOWN_GAPS` 祖父条款 | ~0.5 天 | 回答「接新 agent 漏文档」 |
| **第三批** | `gen-docs-tables.mjs`（三张表 + `--check`） | ~1 天 | 根治 C1（多副本不同步） |
| **第四批** | `AGENTS.md` 拆分、recipe 模板化、§4 标测试 | ~0.5 天 | 让必读部分真的被读完 |
| 可选 | 陈旧雷达 | ~1 天 | 非阻塞提示 |

**顺序不可调**：第一批的 `doc-impact.mjs` 是其余各层的「兜底网」——即使后来某个生成器漏了一处，它仍会提醒「你动了代码却没动任何文档」。

---

## 6. 一句话

这次审计最大的收获不是那 30 条修正，而是证明了：**规范已经足够，缺的是让规范不绿就红的机器。**

`doc-impact.mjs` 一条命令的价值，超过在 `AGENTS.md` 里再写一页——因为它把「记得改文档」变成「不改就提交不了」。
