# 图片、文件与语音

WeMind 支持微信里的文本、图片、语音、文件、视频。图片走 Agent 的 image 输入；文件/视频/无转写语音会先落盘，再把绝对路径交给 Agent。

## 收到的消息

| 类型 | 处理 |
| --- | --- |
| 文本 | 直接进 Agent |
| 图片 | 解密后作为 ACP image block 交给 Agent |
| 语音（微信有转写） | 直接当文本，不再下载 |
| 语音（无转写） | 下载解密，落盘，给绝对路径 |
| 文件 / 视频 | 下载解密，落盘，给绝对路径 |

落盘位置：

- `direct`：`~/.wemind/<账号>/media/inbound`
- `managed`：`<managed>/media/inbound`（worker 任务写到 `worker-home/media/inbound`）

默认保留 30 天、总量 1GB；启动时清理一次，之后每次写入检查，最多每小时清一次。

## 让 Agent 发文件

Agent 在回复里写显式链接：

```markdown
[附件](file:///absolute/path/report.pdf)
[文件](file:///absolute/path/archive.zip)
[视频](file:///absolute/path/demo.mp4)
```

图片：

```markdown
![](../absolute/path/chart.png)
![](https://example.com/chart.png)
```

规则：

- 本地路径必须是绝对路径；含 `)` 时用 `<...>` 包起来。
- 代码围栏和行内代码里的写法只是示例，不会被当成附件。
- 没有附件链接时，正文原样返回，不改 Markdown 代码块。
- 长回复超过约 1500 字，会自动转成 `.md` 文件发送。

## 安全边界

发送前会检查：

- 路径真实解析（realpath）；
- 拒绝 UNC/网络路径（`\\server\share`、`file://host/...`）；
- 拒绝 Windows NTFS 数据流后缀（如 `account.json::$DATA`）；
- 敏感文件名单（账号、登录态、密钥、控制桥、任务目录等）；
- 单文件默认最大 25MB。

需要临时发一个敏感文件时，登录者可以在微信里发：

```text
允许敏感文件
允许敏感文件 5
```

默认开 2 分钟，最长 30 分钟，只在本 daemon 进程内有效，重启即失效。窗口内只跳过敏感名单；UNC、NTFS 数据流、大小上限仍然生效。

## 收件人模式

默认情况下，带附件的消息进聊天大脑。要让附件进某个任务，先指定收件人：

```text
发给任务 2
#2
```

然后发图片/文件，最后用一句话提交：

```text
按这个改，改完告诉我
```

- 附件先暂存，队列安静约 700ms 后再一起提交。
- 3 分钟没有新消息，会自动提交并回执。
- 发 `好了` / `就这样` 立即提交。
- 换收件人时，旧批次先交回原任务。
- `结束任务` 或 `wemind task-stop` 会清掉对应收件人指针和暂存队列。

## 语音

微信有转写的语音直接当文本，**不会**进附件队列。这样语音里的「结束任务」「继续」仍然能被指令层识别。

没有转写的语音才下载落盘。想让它转成文字，需要 Agent 自己处理音频文件。

## 常见问题

**图片发了没反应？** 先看 `wemind log --errors`。有些 Agent 不支持 image block，会在握手/回合里报错。

**文件太大？** 默认 25MB 上限。压缩或拆分后再发。

**Windows 上路径带反斜杠？** 可以，但必须是绝对路径；UNC 路径会被拒绝。

**为什么 Agent 说找不到文件？** 它拿到的是绝对路径，检查这个路径是否在 daemon 所在机器上，以及 Agent 是否有读权限。
